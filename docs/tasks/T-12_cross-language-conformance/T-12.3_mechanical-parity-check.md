## Goal

Fail CI when the Go and Python trees differ in their layers, package names, adapter names or public names beyond what the language forces, by the rule of `contracts/conventions/naming.md` (REQ-ARC-009 to REQ-ARC-011).

## Design notes

- Three comparisons. (1) Folders and file names: `go/internal/` against `python/src/telemetry/internal/` and `go/internal/tests/` against `python/internal/tests/`, ignoring only `__init__.py`, the `_test.go` and `test_` conventions, the `pkg/` and `src/` roots and the extension (REQ-ARC-009). (2) Adapters: `go/pkg/<functionality>/<adapter>` against `python/src/telemetry/<functionality>/<adapter>`, with the exception of adapters that exist in one language (REQ-ARC-011, REQ-AI-011). (3) Public names: exported Go identifiers against Python names through the mechanical rule (`PascalCase` to `PascalCase` for types, `PascalCase` functions to `snake_case`) (REQ-ARC-010).
- The rule is the one written in `naming.md` by T-02.1; the check must not carry a second copy of it. If the rule needs a new case, `naming.md` changes first.
- The extraction of public names reads the Go files with the standard Go parser and the Python files with the `ast` module; neither imports the library.
- A list of allowed differences lives in one small file in the repository, each line with a reason; the check fails on any difference that is not in it.
- It runs in CI next to the architecture tests of T-01.4 and is useful from the first capability: the layout of T-01.2 and T-01.3 is already enough to start.

## Files

- `integration-tests/parity/` (the check itself and its list of allowed differences)
- `go/internal/tests/architecture/` and `python/internal/tests/architecture/` (only if a rule fits an architecture test better than the shared check)
- fixtures: two small trees that agree and two that differ, under `integration-tests/parity/fixtures/`
- the step in the CI workflow of T-01.5

## Documents updated in the same change

`contracts/conventions/naming.md` (only if a case was missing), `docs/architecture/architecture.md` (section 3 and the layout), `docs/deployment/deployment.md` (the CI step), `docs/requirements/requirements.md` (REQ-ARC-009 to REQ-ARC-011), the status table of `README.md`.

## Acceptance criteria

- A folder, a file, an adapter or a public name present in one tree and missing in the other makes the check fail and names both paths.
- The only differences that pass are the ones listed with a reason.
- A new adapter of one language only needs a listed reason, nothing more.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Run the check over the small fixture trees (agree, differ) and over the real repository; rename one file in a branch on purpose and see the CI step fail.
