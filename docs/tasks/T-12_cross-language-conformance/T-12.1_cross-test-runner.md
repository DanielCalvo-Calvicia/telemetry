## Goal

One job in CI runs the shared fixtures through the Go and the Python implementations and compares what they produce: serialization byte for byte, context propagation, the same spool and the same configuration (REQ-CNF-006).

## Design notes

- Each language gets a small helper program that reads a fixture and writes its result as canonical JSON (RFC 8785, REQ-CNF-003) to standard output. The driver runs both and compares the bytes; a difference prints the fixture, both outputs and the first differing position.
- The four checks of REQ-CNF-006: serialization of events (the fixtures of T-02.8, later those of every capability), context propagation (the fixtures of T-10.3 and T-10.6), reading the same spool (a file written by one language and read by the other, T-06.7) and interpreting the same configuration (the same input gives the same validated model or the same error code, REQ-CNF-004).
- The runner is generic: a capability adds a folder of fixtures and a line in a list, never a new driver. Each epic still writes its own scenarios (T-06.7, T-07.5, T-10.6).
- The files that are compared come only from the repository. No network, no real credentials, no internal host names (public repository).
- Open question to the maintainer: PR-001 REQ-CNF-005 names `integration-tests/fixtures/` while the repository rule puts every test under `internal/tests/`. The proposal is read as: shared fixtures and the cross driver in `integration-tests/`, the helper entry points inside each language's own `internal/tests/e2e/`. Confirm.

## Files

- `integration-tests/runner/` (the driver and the comparison; its language is decided here: a Python script or a Go program, to be asked)
- `integration-tests/fixtures/` (shared with T-02.8; one subfolder per capability)
- `go/internal/tests/e2e/cross_helper/` and `python/internal/tests/e2e/cross_helper/` (the two helper programs)
- the job of the CI of T-01.5 (the workflow file) that builds both helpers and runs the driver
- the driver's own tests: `integration-tests/runner/tests/` (a pair of fixtures that agree and a pair that differ)

## Acceptance criteria

- The job runs on every pull request and fails when the two outputs differ for any fixture.
- The four areas of REQ-CNF-006 each have at least one fixture that runs today (serialization from T-02.8; the others when their epic exists, listed as pending until then).
- A deliberately broken fixture (one differing byte) makes the job fail with a readable report.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Run the driver locally with matching and with differing outputs; run the CI job on a branch with a deliberate difference and confirm it fails, then remove the difference.
