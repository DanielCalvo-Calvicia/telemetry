## Goal

Decide whether the library is ready for `1.0`: every capability is stable and the maturity report says so, and the maintainer decides the release (Q09-6, REQ-CNF-008).

## Question

The maintainer answered Q09-6 with option B: `1.0` only when every capability works, and until then the library is a beta (`0.x`). With the maturity report of T-12.4 in hand:

1. Does the report show every capability as `stable` in Go and in Python, with the cross tests green?
2. The OpenTelemetry and Prometheus adapters (T-10.4, T-10.5) and the audit adapter (T-11.4) are deferred until a project needs them. Do they block `1.0`, or is the capability (metrics, traces, audit) complete without them? The report of T-12.4 proposes the second reading; only the maintainer decides it.
3. Do the two pilots that need the maintainer (the Raspberry Pi of T-08.6 and the agent of T-09.9) count as done for devices and AI?
4. Do `schema_version` and the library reach `1.0` in the same release (REQ-VER-001 says `schema_version` reaches `1.0` with the library)?
5. Is there anything in the known risks of PR-001 (no receiver, no Go pilot) that the maintainer wants closed first?

## Resolution

Awaiting the maintainer.

Documents changed by this task once it is answered: a dated note in [ADR-011](../../decisions/ADR-011-adopt-the-telemetry-standard-go-python.md) with the decision and the date; `docs/deployment/deployment.md` (the release rule and the `1.0` row); the status table of `README.md`; `docs/requirements/requirements.md` (REQ-CNF-008); this epic, `docs/tasks/ORDER.md` and the board of the [tasks README](../README.md).
