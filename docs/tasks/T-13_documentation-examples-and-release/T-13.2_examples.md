## Goal

Give every capability a runnable example per language, so a project sees how to import only what it needs and pass the adapters to the core in code (REQ-ARC-013). The item 8 of the definition of done of PR-001 section 17 asks for it.

## Design notes

- One example per capability and language: logging with the console and HTTP destinations, delivery modes, executions and faults, device helpers, AI callbacks and Langfuse, metrics and traces, audit routing. The SQLite destination and the spool get one each.
- The old `examples/aws_http_smoke` moves to the new API in T-04.7 and stays as the example of the AWS HTTP adapter; this task adds the others and the index.
- Each example is small, builds and runs without a network: it sends to a local fake receiver or to a file. A Go adapter example is its own module, listed in `go.work`.
- Inputs are placeholders (`http://localhost`, `my-service`); no real host, token or customer name, because the repository is public. A token is read by the example from its own environment, the library never reads one (ADR-004).
- The examples of Annex B of PR-001 are illustrative until T-08.7 edits them with the real projects; the device examples here follow that edit.
- Open question to the maintainer: are the examples built by CI (compiled and run) or only compiled? The proposed answer is compiled and run, because an example that does not run is a false document.

## Files

- `examples/<capability>/go/main.go` (and a `go.mod` where the example imports an adapter module)
- `examples/<capability>/python/main.py`
- `examples/README.md` (the index: capability, language, how to run)
- `go.work` (the example modules) and the CI workflow of T-01.5 (a step that builds and runs them)
- tests: `go/internal/tests/e2e/` and `python/internal/tests/e2e/` run the examples against the fake receiver of T-04.8

## Documents updated in the same change

`README.md` (quick start and layout), `docs/api/api.md` (a link to the example of each capability), `docs/architecture/architecture.md` (the `examples/` folder), `docs/deployment/deployment.md` (the CI step), `docs/requirements/requirements.md` (the example of each capability is part of its done).

## Acceptance criteria

- Each built capability has an example in Go and in Python that builds and runs against a local fake.
- The index lists each example with the command to run it.
- No example contains a real host, token or customer name.
- Every link of the changed documents resolves.

## Verification

Run every example locally and in CI; grep the examples for hosts, tokens and addresses with the checklist of `docs/security/security.md`; check the links of `examples/README.md`.
