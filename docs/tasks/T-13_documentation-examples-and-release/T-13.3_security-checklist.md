## Goal

Make `docs/security/security.md` and its checklist cover the new redaction, the SQLite files, the spool directory and the rules of the public repository, so the checklist run before every push is complete for the new library.

## Design notes

- Redaction (REQ-SEC-001, REQ-SEC-002, REQ-SEC-008): the default list is added to the detectors of ADR-006 and nothing is removed; the document lists both and says masking happens before any sink.
- The SQLite files: the spool and the SQLite destination hold events on disk, possibly with data a project did not mask enough. The document says where the file lives (a directory the consumer gives), who may read it, that WAL mode creates side files, that retention is the project's job and that the files never go into the repository (the ignore rules of `.gitignore` get the patterns of the database and its WAL side files).
- The spool directory: 256 MiB per destination by default, kept until the project cleans it (Q03-5, Q07-11); the document gives the cleanup function and the permission advice for the directory.
- The public repository: placeholders only in code, examples, fixtures and the inputs of `internal/tests/e2e/deployed_aws_microservice_test.go` (its switch `run_against_deployed_service` is `false` in anything committed); no binary; an incoming trace context is not authorization (T-10.3 adds its line when built).
- The dependency of T-03.4 only covers the redaction. The spool and SQLite files come from T-06 and the audit warning from T-11.3, so this task is done in two passes: now for the redaction and the repository rules, and again when T-06 exists (the epic T-13.1 sync catches it).

- The document states what is built and what is planned for each line.

- Every link of the changed documents resolves.
