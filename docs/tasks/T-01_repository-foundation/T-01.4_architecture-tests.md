## Goal

Make the direction of dependencies a test in both languages, so a wrong import fails before review (REQ-ARC-008).

## Design notes

- Rules to check (REQ-ARC-001, REQ-ARC-002, REQ-ARC-003): the domain imports nothing from the other layers and no HTTP, database, file system, OpenTelemetry, driver or AI framework package; the application defines the ports and imports only the domain; only a composition root imports concrete outbound adapters; the I/O of an adapter lives in its `external/` folder; a consumer never imports `internal/`.
- The old library already has such a test under `internal/tests/`; reuse its idea and keep it running on the old code until T-04.7. The new tests start on the empty layers and grow with them.
- Go: the checker reads the import lists with `go/parser` of the standard library, so no dependency is added (the `golang.org/x/tools/go/packages` option in the plan is not needed). Python: a test that parses the imports of each module with the standard `ast` module (no new dependency).
- Each rule has a "planted violation" case: a fixture package that breaks the rule and is expected to be reported. It lives under `fixtures/` and is never imported by the library.
- Names follow descriptive snake_case; tests are black-box (`package x_test`).

## Acceptance criteria

- On the empty layers of `go/` and `python/` all architecture tests pass.
- Each rule has a planted violation that makes its test fail, in Go and in Python.
- A failing test names the offending file and the forbidden import in its message.
- The architecture test of the old library still passes.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

`go test ./internal/tests/architecture/... -count=1` inside `go/`; the architecture tests of `python/`; a manual run with a violation added on a scratch branch (not committed) to read the failure message.

## Notes

**Done 2026-10-28** (Go 1.25.5, Python 3.11.1, Windows).

- **What was built.** The six rules of the architecture document (section 2.2) in a rule engine per language, with a `Violation` that names the rule, the file and the import. Go: `go/internal/tests/architecture/checker/{violation,imports,rules}.go` (imports read with `go/parser`), the three test files of the plan and `helpers_test.go`. Python: `python/internal/tests/architecture/{checker,helpers}.py` and the three test modules (`test_dependency_direction.py`, `test_composition_root.py`, `test_internal_visibility.py`, which was added to mirror Go). Python also resolves relative imports against the file's own package (one more test).
- **Planted violations.** Nine Go cases under `go/internal/tests/fixtures/architecture/testdata/` and nine Python cases under `python/internal/tests/fixtures/architecture/` (the clean tree, domain to infrastructure, domain to I/O, domain to a telemetry backend (Go only), application to an adapter, infrastructure to the composition root, I/O outside `external/`, an adapter outside the composition root, a consumer that imports `internal/`; Python adds a relative import). `testdata` is ignored by the Go tool, and ruff excludes the Python fixtures (`extend-exclude` in `pyproject.toml`).
- **Verification.** Go, inside `go/`: `gofmt -l` prints nothing; `go vet`, `go build` and `go test ./... -count=1` pass; coverage of `./internal/...` is 98.6% (the gate is 95%; the first version had 86.7% because of untested error branches, so the checker was simplified to one folder loop and three tests were added: a backend import, a file that cannot be parsed and a root that cannot be read). Python, in a clean virtual environment with the package installed: 14 tests pass; `ruff check` and `ruff format --check` pass. **Manual run of a planted violation in the real tree** (not kept): a file `go/internal/domain/zz_planted.go` that imports `net/http` failed with `domain-isolated: internal/domain/zz_planted.go imports "net/http"`, and a file `python/src/telemetry/internal/domain/zz_planted.py` that imports `http.client` failed with the same kind of message. Both files were removed.
- **Plan changes.** The plan said the Go test might use `golang.org/x/tools/go/packages` and asked the maintainer before adding a dependency; the standard library was enough, so no dependency was added. `doc.go` of the Go architecture folder was removed because the folder has tests now. `internal_visibility` has a Python test too, and the Go checker lives in its own package so the three test files and the fixtures share one engine.
- **The old library.** The acceptance line "the architecture test of the old library still passes" has nothing to run: the old library has no architecture test (its `internal/tests/` holds `composition_root`, `e2e` and `logging`). The root module's tests were not touched.
- **Left for later.** The CI step that runs these tests is T-01.5. The rules about adapters start to bite when the adapters exist (T-04).
