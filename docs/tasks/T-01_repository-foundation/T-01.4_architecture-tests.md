## Goal

Make the direction of dependencies a test in both languages, so a wrong import fails before review (REQ-ARC-008).

## Design notes

- Rules to check (REQ-ARC-001, REQ-ARC-002, REQ-ARC-003): the domain imports nothing from the other layers and no HTTP, database, file system, OpenTelemetry, driver or AI framework package; the application defines the ports and imports only the domain; only a composition root imports concrete outbound adapters; the I/O of an adapter lives in its `external/` folder; a consumer never imports `internal/`.
- The old library already has such a test under `internal/tests/`; reuse its idea and keep it running on the old code until T-04.7. The new tests start on the empty layers and grow with them.
- Go: the test loads the packages of the module and checks their import lists with the standard library or with `golang.org/x/tools/go/packages` (a test-only dependency: ask the maintainer before adding it). Python: a test that parses the imports of each module with the standard `ast` module (no new dependency).
- Each rule has a "planted violation" case: a fixture package that breaks the rule and is expected to be reported. It lives under `fixtures/` and is never imported by the library.
- Names follow descriptive snake_case; tests are black-box (`package x_test`).

## Acceptance criteria

- On the empty layers of `go/` and `python/` all architecture tests pass.
- Each rule has a planted violation that makes its test fail, in Go and in Python.
- A failing test names the offending file and the forbidden import in its message.
- The architecture test of the old library still passes.
- Ends with the checks of the README section 3 green in every language the task names.
