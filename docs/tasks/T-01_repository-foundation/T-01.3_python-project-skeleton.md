## Goal

Create the installable Python package `telemetry` with the layers of the Go core and an empty, working test tree.

## Design notes

- REQ-DST-002 and Q07-3: one package `telemetry` with the extras `sqlite`, `otel`, `prometheus` and `ai`, installed from Git (no package index): `pip install "telemetry[sqlite] @ git+https://github.com/DanielCalvo-Calvicia/telemetry@python-vX.Y.Z#subdirectory=python"`. Python >= 3.10 (Q06-2, Q07-6; the pilot runs 3.11.4).
- REQ-ARC-009 and REQ-ARC-014: the same layers, directory names and file names as Go. The internal root is `python/src/telemetry/internal/` with `domain/`, `application/`, `infrastructure/`, `composition_root/`; the public packages are `telemetry.<functionality>.<adapter>` (REQ-ARC-012). The tests root `python/internal/tests/` mirrors the code and has the same folders as the Go tests root.
- Q07-8: PEP 8 names and the Go layers are the rule until the Python standard of the organization can be read (it exists but is not reachable now). Write the rules in the architecture document.
- The extras may be empty lists in this task: the adapters arrive with their capabilities. The core has no third-party dependency (REQ-ARC-005).
- Open for the maintainer, recorded in the architecture document before use: the build backend, the test runner and the linter and formatter (T-01.5 runs them). Pick the ones with the fewest dependencies and write the reason.
- The Python names of the public packages are the open point 2 of T-01.1.

## Acceptance criteria

- In a clean virtual environment, `pip install` of the `python/` subdirectory (from a local path and from the Git URL of a branch) succeeds and `import telemetry` works with no third-party package.
- `pip install ".[sqlite,otel,prometheus,ai]"` resolves (empty extras are allowed).
- The folder names of `python/src/telemetry/internal/` and `python/internal/tests/` equal those of Go, except what the language forces (`__init__.py`, `src/`).
- The test tree runs and passes with one test.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

A script or CI step that creates a clean virtual environment, installs the package from the path and runs the test tree; the same install from the Git URL once the branch is pushed (by the maintainer: never push here).
