## Goal

Create the directories of the standard and the new Go core module, without touching the old library.

## Design notes

- Q07-1 and Q07-2: the Go module moves to `go/`, its path is `github.com/DanielCalvo-Calvicia/telemetry/go` and it starts at `go/v0.3.0`. Go version `1.25.5` or newer, as the root `go.mod` today (REQ-DST-003).
- The root `go.mod` (module `github.com/DanielCalvo-Calvicia/telemetry`) stays with the old `pkg/logging` and `internal/logging`. A nested `go/go.mod` makes `go/` a module of its own, so the root module does not contain it. T-04.7 removes the old code.
- `go.work` is committed at the root and lists the root module (while the old library lives), `./go` and, later, each adapter (ADR-013). Open point for T-01.1: whether the old module stays listed until T-04.7.
- The core module starts with the empty layers of REQ-ARC-014 under `go/internal/` (`domain/`, `application/`, `infrastructure/`, `composition_root/`) and an empty tests root with `architecture/`, `fixtures/`, `contract/`, `domain/`, `application/`, `infrastructure/`, `composition_root/`, `e2e/`. Empty folders carry a `doc.go` or are created by the task that needs them: a folder with no file is not in Git.
- To verify here (ADR-013, known risks of PR-001): a package under `go/internal/` can be imported from a nested module at `go/pkg/<functionality>/<adapter>/`, because the Go rule is by path. Prove it with a throwaway test module and write the result in the architecture document.
- `contracts/` and `integration-tests/` get only a `README.md` that says what the folder is for; T-02.1 fills `contracts/`.

## Acceptance criteria

- `go build ./...` and `go test ./...` pass inside `go/` and, unchanged, in the root module; the old library keeps its tests and its coverage.
- `go work sync` and `go list -m all` work from the root; the core module path is exactly `github.com/DanielCalvo-Calvicia/telemetry/go`.
- A package under `go/internal/` imports from a nested test module under `go/pkg/` (result recorded), or the problem is written as a question to the maintainer.
- No real secret, host or account id in any new file; `.env.example` is unchanged.
- Ends with the checks of the README section 3 green in every language the task names.
