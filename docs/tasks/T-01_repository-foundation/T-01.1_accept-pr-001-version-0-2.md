## Goal

Get the maintainer's decision on PR-001 version 0.2 before any file of the new layout is created.

## Question

Does the maintainer accept [PR-001](../../proposals/PR-001-telemetry-standard-go-python.md) version 0.2, or correct it? The proposal lists what is still open ("Still to decide"):

1. Acceptance of this version as a whole.
2. The Python names. They are meant to mirror the Go ones (`telemetry.<functionality>.<adapter>`, installed as `telemetry`); this is a reading of the answer to Q08-2 that needs confirmation. T-01.3 and T-03.9 depend on it.

Two questions the plan adds, because tasks cannot start without them:

3. The public package that holds the entry point `New(config, adapters...)` of the Go core. REQ-ARC-012 names `go/pkg/<functionality>/<adapter>` but not the package of the core itself (see T-03.9).
4. Whether the root `go.mod` of the old library stays while `go/` has its own module until T-04.7 (the reading of T-01.2), or the old library moves first.

## Resolution

Answered by the maintainer on 2026-10-28:

1. PR-001 version 0.2 is accepted as it is. ADR-011, ADR-012 and ADR-013 are Accepted.
2. The Python names are `telemetry.<functionality>.<adapter>`, installed as `telemetry`.
3. The public package of the Go core, with `New(config, adapters...)`, `Shutdown` and the shared types, is `go/pkg/telemetry`.
4. The root `go.mod` of the old library stays beside the new `go/go.mod` until T-04.7 removes the old library; `go.work` joins them.
