## Goal

One pipeline that checks every Go module and the Python package on each pull request and each push to `main`, with the same gates the maintainer runs by hand.

## Design notes

- Today `.github/workflows/ci.yml` runs `go vet`, the tests and a 95% coverage gate (without `external/`) for the single module, with a read-only `GITHUB_TOKEN` and actions pinned by commit SHA. Keep those properties.
- Per Go module (the core and, later, each adapter, found from `go.work`): `gofmt -l .` and `goimports -l .` print nothing, `go vet`, `go build`, `go test -count=1`, and the coverage of `internal/` without `external/` at 95% or more (REQ-ARC-008, Q06-7). The race detector needs cgo and stays out (CLAUDE.md).
- Python: format and lint, the tests, and the same 95% gate without the `external/` folders (Q06-7). The tools are the ones chosen in T-01.3.
- A job `generated-code` that regenerates and fails on a difference is added by T-02.4. A job `cross-tests` that runs the Go and Python fixtures together is created empty here and filled by T-12 (REQ-CNF-006).
- The old root module keeps its job until T-04.7 removes it.
- No secret, internal host or account id in the workflow. The e2e test of the deployed service stays off: its switch is `false` in anything committed.
- Open for the maintainer: which Python versions the matrix covers (the minimum 3.10 and the 3.11 of the Raspberry Pi are the candidates).

## Acceptance criteria

- A pull request runs one job per Go module and one for Python; each fails on a format error, a vet or lint error, a failing test or a coverage below 95%.
- The coverage total excludes every `external/` folder, in both languages.
- The workflow keeps `permissions: contents: read` and pinned action SHAs.
- A job named `cross-tests` exists and passes while empty.
- The deployment document describes exactly the jobs of the file.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Run the commands of every job locally; read the Actions result of a pushed branch only when the maintainer pushes it (never push from here).
