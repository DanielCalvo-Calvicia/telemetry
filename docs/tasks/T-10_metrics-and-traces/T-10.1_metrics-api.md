## Goal

Let a project record counters, up/down counters, gauges, histograms and durations, each with a name, a description and a unit, with a limit on the number of series so a bad attribute cannot grow memory without bound.

## Design notes

- The instruments are created through the public entry point of the core (T-03.9) and emit to a new outbound port `MetricsSinkPort`; without a sink they are cheap and do nothing (the library is passive).
- Name, description and unit are value objects; an instrument without them is a classified error, never a panic or an exception (ADR-005).
- Cardinality (REQ-MET-003): the limit is per metric and configurable; past it, new series are grouped under the attribute value `overflow` and the event is recorded in diagnostics (T-05.5, covered by the epic dependency on T-05).
- High-cardinality identifiers (`execution_id`, `request_id`, REQ-CTR-006) are never metric attributes. Open question to the maintainer: when a project passes one, is the attribute dropped and counted in diagnostics, or is the call rejected with an error code? The default of the cardinality limit is not in PR-001 either and is to be fixed here.
- Open question to the maintainer: with no OpenTelemetry or Prometheus adapter, where do the values go? PR-001 section 7.2 gives console, file and HTTP no metrics, while Q02-5 names `metric.*` events. Does the core ship an in-memory reader or a `metric.*` event, or is a fake sink in the tests enough until T-10.4 and T-10.5 exist?
- Names follow the mechanical rule of `contracts/conventions/naming.md` (T-12.3).

## Acceptance criteria

- Each of the five instrument kinds records a value and reaches a fake `MetricsSinkPort`.
- A metric with no name, no description or no unit is refused with a classified error, not an exception.
- Past the limit, new series go to `overflow` and diagnostics shows it; existing series keep counting.
- No identifier named in REQ-CTR-006 becomes an attribute, in the way the maintainer chooses.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Unit tests of the value objects, the cardinality rule and the service with a fake sink in both languages; the architecture tests (the domain imports nothing from the other layers); coverage of 95% or more without `external/`.
