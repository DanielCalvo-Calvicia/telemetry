## Goal

Expose the metrics of the library in the native Prometheus protocol (REQ-OUT-004). **Deferred until a project has a backend** that scrapes it (Q08-8).

## Design notes

- The adapter implements `MetricsSinkPort`. It carries no traces and no events (PR-001 section 7.2).
- Open question to the maintainer, to answer when a backend exists: how are the metrics exposed? Prometheus scrapes an endpoint, so the adapter either serves one (and then the project decides the listener, the port and its protection) or offers a handler that the project mounts. Nothing is decided; the library opens no listener by itself while it is passive.
- The mapping of units, names (`_total`, `_seconds`) and the `overflow` series is written here when the adapter is built.
- In Go it is a module of its own with its own tag (ADR-013); in Python it is the extra `telemetry[prometheus]`. The core never imports it (REQ-ARC-013).
- No fixed address and no credentials in the repository (REQ-SEC-007).
