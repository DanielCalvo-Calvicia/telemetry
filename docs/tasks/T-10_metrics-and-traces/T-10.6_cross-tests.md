## Goal

Prove that a trace that starts in Go and continues in Python keeps one trace id, and the other way round, so the capability counts as supported in both languages (REQ-CNF-006, REQ-CNF-007).

## Design notes

- The test runs on the runner of T-12.1: a Go program starts a span, injects the context into headers and prints them; a Python process extracts them, starts a child span and reports its ids; the test compares. Then the same in the other direction.
- It also feeds the shared fixture of valid and invalid `traceparent` values (T-10.3) to both implementations and compares the result (new trace or same trace).
- The metrics have no cross wire format today because there is no backend. The test compares only what both languages can observe: instrument names, units and the `overflow` behavior after the limit, through a recording sink that prints a canonical JSON of what it received.
- Open question to the maintainer: if T-10.1 decides that metrics produce `metric.*` events, this task also compares them byte for byte.
- The test needs no network: the two programs exchange the headers through files or standard input.

## Acceptance criteria

- A trace started in Go is continued in Python with the same trace id and the span as parent, and the reverse holds.
- Both languages give the same result for every header of the fixture.
- The cross test fails when either language changes its behavior.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Run the cross job of CI locally (the command of T-12.1) and break one side on purpose to see it fail; run the helper programs alone in each language.
