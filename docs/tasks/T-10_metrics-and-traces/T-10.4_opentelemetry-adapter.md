## Goal

Send metrics and spans to an OpenTelemetry collector in native OTLP, never in the own schema (REQ-OUT-004). **Deferred until a project has a backend** (Q08-8).

## Design notes

- The adapter implements `MetricsSinkPort` and `TraceSinkPort` with the OpenTelemetry SDK of each language. Its dependencies never reach the core (REQ-ARC-005, REQ-DST-001).
- In Go it is a module of its own, with its own `go.mod`, a minimum core version and its own tag (ADR-013). In Python it is the extra `telemetry[otel]` (REQ-DST-002).
- The project imports it and passes it to the core in code; it never registers itself on import (REQ-ARC-013).
- Open questions to the maintainer, to answer when a backend exists: the Go path (PR-001 lists one OpenTelemetry row for logs, metrics and traces, while Q09-3 asks for one module per adapter, so is it one module that serves metrics and traces, or one per functionality?), and whether the logs of that row are included.
- The endpoint, the protocol (gRPC or HTTP) and the credentials come from the configuration the consumer passes in: no fixed URL, no secret in the repository (REQ-OUT-005, REQ-SEC-007).
- Export failures follow ADR-005 and appear in diagnostics.

## Files

- `go/pkg/<functionality>/opentelemetry/go.mod` and its `external/`, `error/` and `helpers/` folders (`<functionality>` is the open question above)
- `python/src/telemetry/<functionality>/opentelemetry/` with the same folders, and the `otel` extra in `python/pyproject.toml`
- tests mirroring the code under `go/pkg/<functionality>/opentelemetry/internal/tests/` and `python/internal/tests/`, with a fake OTLP receiver as fixture
- the line of the adapter in `contracts/capabilities/registry.yaml`

## Acceptance criteria

- A recorded metric and a finished span arrive at a fake OTLP receiver in the native format.
- Importing the core alone does not download the OpenTelemetry packages.
- A receiver that fails never fails the caller.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Adapter tests against a fake OTLP receiver in both languages; a check that the `go.mod` of the core has no OpenTelemetry dependency.
