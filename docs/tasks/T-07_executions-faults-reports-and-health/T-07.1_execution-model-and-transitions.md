## Goal

Write the eight execution states and their valid transitions once, in `contracts/`, and implement the state machine in the domain of Go and of Python, so both reject the same invalid transitions (REQ-EXE-001 to REQ-EXE-003).

## Design notes

- States (REQ-EXE-002): `started`, `in_progress`, `completed`, `failed`, `cancelled`, `timed_out`, `retrying`, `degraded`. Terminal states (REQ-EXE-003): `completed`, `failed`, `cancelled`, `timed_out`; no transition leaves them.
- The transitions live in `contracts/enums/execution_transitions.yaml` as "from state: list of reachable states". The generator (T-02.4) emits the table for both languages; the domain imports nothing, so it uses the generated table and never reads the YAML at run time.
- An invalid transition returns a classified error (a sentinel in `domain/errors.go`, an exception in Python, the same error code in both, T-03.7). It never panics and never reaches the destination (ADR-005).
- The state of an execution is a value object; an execution is an entity (id, parent id, attempt, state). The domain measures durations with the monotonic clock only through `ClockPort` (REQ-CTR-008).
- Questions to the maintainer (the specification gives the states and the terminal ones, not the matrix):
  1. Which transitions are valid? In particular: can `started` go straight to a terminal state; from which states is `retrying` entered and where does it go; does `degraded` return to `in_progress`?
  2. Who creates `execution_id`: the library (UUIDv7 through `IDGeneratorPort`) or the consumer, or either?

## Acceptance criteria

- The 64 pairs of states give, in Go and in Python, the result written in `execution_transitions.yaml`.
- Every terminal state rejects every outgoing transition, and the rejection carries the same error code in both languages.
- A wrong state name is rejected with a classified error that names the value.
- The domain imports nothing from another layer (the architecture tests of T-01.4 stay green).

Ends with the checks of the README section 3 green in every language the task names.
