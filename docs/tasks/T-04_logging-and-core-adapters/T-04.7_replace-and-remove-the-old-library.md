## Goal

Remove `pkg/logging` and `internal/logging`: from here the new library is the only one in the repository (Q01-3, Q01-5).

## Design notes

- No deprecation period and no wrapper. The only consumer of the old API takes the old tags (`v0.1.0`, `v0.2.0` of the old module path) from the published package, which stays available (PR-001, "How it relates to what exists today").
- The examples (`examples/aws_http_smoke`) and the tests move to the new API. The tests of the old library that cover behavior that stays (masking, call context, the sinks) are rewritten against the new code, not just deleted: the 95% gate must hold after the removal.
- The sample service uses the AWS HTTP adapter as a module of its own, so it also proves a project can import it from a nested module.
- ADR-002 and ADR-003 get a dated "replaced" note that points to ADR-013 (ADR-013 says it replaces them when built). ADR-005 gets a dated note: the rule stays, the synchronous send and the "never retries" text go with the queue of T-05. ADR-008 and ADR-009 get a note on what changed.
- This task does not release anything and does not tag; the consumer note is T-13.6.
- Question to the maintainer: should the old `.env.example` and the old environment-variables document be rewritten here, or only when T-03.6 tags exist? The table of CLAUDE.md asks for them in the same change as the `Config` fields.

## Notes

**Done 2026-11-03.** The old library is gone from the tree; the new library is the only one. Asked of the maintainer before starting, with the answers: the e2e test is ported with the user's local values kept in an ignored file, and the root Go module is removed.

- **Removed.** `pkg/logging/`, `internal/logging/`, `internal/composition_root/`, `internal/tests/` (the old tests and the old e2e), the old `examples/aws_http_smoke`, and the root `go.mod` and `go.sum` (`.` leaves `go.work`). The tags `v0.1.0` and `v0.2.0` are untouched and stay on the Go proxy.
- **Moved or rewritten.** The e2e test is now `go/pkg/logging/aws_http/internal/tests/e2e/deployed_aws_microservice_test.go`, against the AWS adapter, with `run_against_deployed_service = false` and placeholders. **The maintainer's own values** (switch on, a real log group) were copied before the removal to `deployed_aws_microservice_test.go.local` in the same folder; `*.local` is now in `.gitignore`, so it is never committed (it still holds the old API and must be adapted by hand: copy the constants into the new file when you run it). The sample is `examples/aws_http_smoke`, a **module of its own** (`go.mod`, in `go.work`) that imports the core and the adapter module with local `replace` lines, so it also proves that a project can import the adapter. It was run against a local test server: 12 requests (the DEBUG line is below the minimum), the password masked in both destinations.
- **Tests.** No test of the old library was ported here: the behavior that stays (masking, call context, the sinks) was rewritten in T-03 and T-04.1 to T-04.6, so the removal loses no coverage: Go `go/` **98.4%** (excluding `external/`), the AWS adapter module 98.2%, Python 100%.
- **CI.** `go.work` no longer lists the root; the sample is in the matrix and has no coverage gate (`if` on the steps, no tests).
- **Documents.** README rewritten (status, quick start in Go and Python, layout, checks); the API, architecture, configuration, monitoring, security and requirements documents and `.env.example` describe only the new library; dated notes on ADR-002, ADR-003, ADR-005, ADR-008 and ADR-009; deployment and the registry updated.
- **Known gaps.** `CLAUDE.md` still describes the old layout in places (it is the maintainer's instruction file, so it was not edited here); the AWS adapter module still has the `v0.0.0` placeholder and the local `replace` (T-13.4); CI has not run on GitHub.
