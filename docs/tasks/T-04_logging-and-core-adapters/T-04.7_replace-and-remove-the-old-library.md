## Goal

Remove `pkg/logging` and `internal/logging`: from here the new library is the only one in the repository (Q01-3, Q01-5).

## Design notes

- No deprecation period and no wrapper. The only consumer of the old API takes the old tags (`v0.1.0`, `v0.2.0` of the old module path) from the published package, which stays available (PR-001, "How it relates to what exists today").
- The examples (`examples/aws_http_smoke`) and the tests move to the new API. The tests of the old library that cover behavior that stays (masking, call context, the sinks) are rewritten against the new code, not just deleted: the 95% gate must hold after the removal.
- The sample service uses the AWS HTTP adapter as a module of its own, so it also proves a project can import it from a nested module.
- ADR-002 and ADR-003 get a dated "replaced" note that points to ADR-013 (ADR-013 says it replaces them when built). ADR-005 gets a dated note: the rule stays, the synchronous send and the "never retries" text go with the queue of T-05. ADR-008 and ADR-009 get a note on what changed.
- This task does not release anything and does not tag; the consumer note is T-13.6.
- Question to the maintainer: should the old `.env.example` and the old environment-variables document be rewritten here, or only when T-03.6 tags exist? The table of CLAUDE.md asks for them in the same change as the `Config` fields.

## Acceptance criteria

- `pkg/logging` and `internal/logging` do not exist; nothing imports them.
- `go doc` of the new public packages shows a doc comment on every exported identifier that starts with its own name.
- The coverage of `internal/`, without `external/` folders, is at least 95% in Go and in Python.
- Every document in the list above says only what is true; every link resolves.
- Nothing in the repository holds a secret, an internal host or a binary.
