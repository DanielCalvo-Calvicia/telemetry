## Goal

Write events to the standard output of the process, as JSON or as readable text, with a configurable level (REQ-LOG-001, REQ-LOG-003).

## Design notes

- Two formats: one JSON object per line (the envelope in its canonical form, T-02.5) and a human-readable line (time, severity, category, function, message, attributes). The readable line never prints more than the masked event holds.
- The level is a setting of the adapter: an event below it is not written. ADR-007 makes the minimum level follow the environment today; the library still never reads the environment (ADR-004), so the consumer passes the level in.
- The console is also the fallback of ADR-005 today. Its role in the new design belongs to T-05.5 (diagnostics channel); this task only writes events.
- A write error is classified and returned to the caller of the adapter, never to the log call (ADR-005).
- Question to the maintainer: console, file and HTTP implement the log port now and the event port when `report.*` arrives (T-07). Do they live under `outbound/logging/` (the reference tree of REQ-ARC-014 has that folder) or under a neutral folder?

## Acceptance criteria

- The JSON output of Go and Python is byte-identical for the same event.
- The readable output shows time, severity, category, function and message.
- An event below the configured level is not written.
- A failing writer returns a classified error and does not panic or raise.

Ends with the checks of the README section 3 green in every language the task names.
