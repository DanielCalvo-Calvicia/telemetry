## Goal

Write once per language the HTTP pieces every HTTP adapter reuses: client, TLS, authentication, timeouts, retry policy, batch body and response classification (REQ-OUT-005, REQ-OUT-006).

## Design notes

- Authentication: a bearer token (`Authorization` header) and an API key in a custom header whose name is configurable (REQ-OUT-008, Q08-6). The values come from the configuration the consumer passes in; they never appear in logs, errors or diagnostics (REQ-SEC-007).
- TLS verification is on by default; turning it off needs an explicit setting (REQ-SEC-005). No URL is fixed in code (REQ-OUT-005).
- Batch body: one JSON object `{"schema_version": "0.1", "events": [...]}` with canonical envelopes; optional gzip with `Content-Encoding: gzip` (REQ-OUT-010, Q08-7). The batch limit of T-03.5 (1 MiB) is applied before sending.
- Response classification follows the matrix of 10.6: network error, timeout, 408, 429 and 5xx are transient; other 4xx are permanent; a response that cannot be read is transient with a limit. `Retry-After` on 429 is read as seconds or as an HTTP date.
- Retry policy: exponential backoff with jitter (the exact jitter instants may differ between languages, section 13.1). This task provides the policy as a reusable piece; T-05.3 decides which destination uses it. Open point for the maintainer: 10.1 says `best_effort` makes "one send attempt (or the configured retries)". Does `best_effort` send exactly once?
- Timeout of 3 s by default (REQ-DLV-004, REQ-DLV-006); no network call waits without a timeout.
- Question to the maintainer: Python HTTP library. REQ-ARC-005 asks for a minimal core, so the proposal is the standard library; say if a third-party one is wanted.

## Acceptance criteria

- Both languages produce the same batch body bytes, plain and gzipped, for the same events.
- Every row of the classification fixture gives the expected class; `Retry-After` in both forms is honored.
- With TLS verification on, a server with an untrusted certificate is refused; turning it off needs the explicit setting.
- The token and the key value never appear in an error, a log or a diagnostic.
- A server that never answers ends at the timeout.

Ends with the checks of the README section 3 green in every language the task names.

## Verification

Tests against a local test server (`localhost`) that answers each status, delays beyond the timeout and presents a self-signed certificate; pure tests of the helpers; the fixtures compared in both languages.

## Notes

**Done 2026-11-03** (Go 1.25.5, Python 3.11.1). The coordinator wrote the contract (the settings schema, the table of variables and `.env.example`) and six shared files first, with the expected values computed independently with Node.js; two agents wrote the code in parallel; the coordinator verified independently, ran a differential test and wrote the documents.

- **Built.** The settings and their validation, the batch body and gzip, the authentication header, the classification, `Retry-After`, the backoff with jitter, the retry decision and a client that returns a classified `Outcome`, in both languages with the standard library only. See section 2.19 of the architecture document.
- **Two mistakes found by the verification, none in the product's favor.** (1) The coordinator's reference model for the settings used the URL parser of Node, which fills in a host for `https:///path`; both agents reported that the fixture contradicted its own description and the fixture was corrected (the agents had not edited it). (2) A **differential test of 6000 random inputs** (settings, `Retry-After` values, statuses, backoff, authentication) found two real differences: Python accepted more date forms than Go and Go accepted a port above 65535. Python was made strict (only the IMF-fixdate and the asctime forms) and both now require a port from 1 to 65535; the second run gave **0 differences**.
- **Verification.** All six shared files pass in Go and Python with no edit by the agents. One expected value changed on purpose (`backoff.json`) made both languages fail, restored both pass. Go: `gofmt` and `goimports` clean, vet and build clean, all tests pass (architecture included), coverage **98.2%**; `go.mod` still has no `require` line. Python: `ruff` clean, **498 tests**, coverage **100%** (`external/` is omitted by the repository configuration); `pyproject.toml` still has no runtime dependency. The registry: `REQ-OUT-005`, `REQ-OUT-006`, `REQ-OUT-008`, `REQ-OUT-010`, `REQ-SEC-005`, `REQ-SEC-007` and `REQ-DLV-004` have tests (42 of 130 covered, 80 pending, 8 without a task).
- **Open questions, decided with the defaults (the maintainer was not asked).** Python uses the standard library only. `best_effort` is not decided here: the client sends once and offers the retry policy; T-05.3 decides who retries.
- **Deviations.** The task asked for the same gzipped bytes in both languages; two gzip encoders give different bytes, so the compressed body is checked by decompressing it (the header has no modification time and no name). The fixtures are `batch_body.json` and the others, not `batch_body_two_events.json(.gz)`. The settings schema and its env names were added (the task asked for the HTTP tags).
- **Choices.** Authentication over plain `http` is refused unless the host is local. A redirect is never followed and is permanent. A refused certificate is transient (the certificate may be renewed). `Retry-After` is cut to 24 hours. A port must be 1 to 65535. An error reading the body keeps the status and is transient. The client builds no proxy from the environment.
- **Known gaps.** No rate limiter (REQ-OUT-006 lists rate limits; `Retry-After` is honored). The TLS tests of Python need the `openssl` command (they are skipped without it; CI has it). The URL parser of each language decides some exotic URLs (the fixtures use simple ones).
