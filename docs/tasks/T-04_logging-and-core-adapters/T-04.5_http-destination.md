## Goal

The default destination of the library (REQ-OUT-002): it sends batches of events to the URL the consumer configures, and a failure of it never stops the other destinations (REQ-DLV-005).

## Design notes

- It implements the log port, and the event port when `report.*` arrives (same folder question as T-04.2), on top of the shared infrastructure of T-04.4. It adds only the semantics of the payload (REQ-OUT-006).
- The destination takes a batch and returns a classified result (sent, transient failure, permanent rejection). It does not queue and does not retry on its own: the queue is T-05.1 and the retry is T-05.3.
- The URL is always required. A configuration with the HTTP destination and no URL fails at start with the field and the reason (REQ-OUT-002, REQ-CFG-002). The profiles use this destination by default (REQ-OUT-002).
- A failure is returned as a value to the worker; it never raises or panics into the caller (ADR-005).
- The receiver does not exist yet (Q03-1, Q07-9): every test uses the fake of T-04.8 and no real address appears in the repository.
- The contract the destination sends is the one written in T-04.4; it is the contract a future receiver has to accept.

## Acceptance criteria

- Events logged through the destination arrive at a fake receiver as the batch body of REQ-OUT-010.
- A receiver that answers 5xx, 429, 4xx or does not answer gives the classified result and does not stop a second destination in the same run.
- No URL means a configuration error at start that names the field.
- Go and Python send the same body for the same events.

Ends with the checks of the README section 3 green in every language the task names.
