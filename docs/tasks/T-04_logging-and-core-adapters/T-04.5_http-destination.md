## Goal

The default destination of the library (REQ-OUT-002): it sends batches of events to the URL the consumer configures, and a failure of it never stops the other destinations (REQ-DLV-005).

## Design notes

- It implements the log port, and the event port when `report.*` arrives (same folder question as T-04.2), on top of the shared infrastructure of T-04.4. It adds only the semantics of the payload (REQ-OUT-006).
- The destination takes a batch and returns a classified result (sent, transient failure, permanent rejection). It does not queue and does not retry on its own: the queue is T-05.1 and the retry is T-05.3.
- The URL is always required. A configuration with the HTTP destination and no URL fails at start with the field and the reason (REQ-OUT-002, REQ-CFG-002). The profiles use this destination by default (REQ-OUT-002).
- A failure is returned as a value to the worker; it never raises or panics into the caller (ADR-005).
- The receiver does not exist yet (Q03-1, Q07-9): every test uses the fake of T-04.8 and no real address appears in the repository.
- The contract the destination sends is the one written in T-04.4; it is the contract a future receiver has to accept.

## Acceptance criteria

- Events logged through the destination arrive at a fake receiver as the batch body of REQ-OUT-010.
- A receiver that answers 5xx, 429, 4xx or does not answer gives the classified result and does not stop a second destination in the same run.
- No URL means a configuration error at start that names the field.
- Go and Python send the same body for the same events.

## Notes

**Done 2026-11-03** (Go 1.25.5, Python 3.11.1). The coordinator wrote the contract (the setting the destination adds, the table of variables, `.env.example`) and the shared cases first (the expected bytes and results computed independently with Node.js); two agents wrote the code in parallel; the coordinator verified independently and wrote the documents.

- **Built.** The HTTP destination (both ports), its settings and validation, the mapping of an outcome to the result, `Deliver` with the full outcome, `NextDelay`, the dependencies file and the public packages. See section 2.22 of the architecture document.
- **Verification.** The 13 request cases and the 5 settings cases pass in Go and Python with no edit by the agents (one expected count changed on purpose made both fail, restored both pass); the public names are checked in both. The acceptance criteria are tests: a failing receiver (503, 429, 408, 4xx, a redirect, a closed port, a server that never answers) gives the classified result and does not stop a console destination in the same core. Go: `gofmt` and `goimports` clean, vet and build clean, all tests pass (architecture included), coverage **98.1%**; `go.mod` still has no `require` line. Python: `ruff` clean, **634 tests**, coverage **100%**. The registry: `REQ-OUT-002` has tests (45 of 130 covered, 77 pending, 8 without a task); `REQ-ARC-014` moves to T-04.6.
- **Open question, decided with the default.** `best_effort` is not decided here: the destination sends once; T-05.3 decides who retries. The folder is `outbound/logging/http/`. The maintainer was not asked.
- **Interpretation to confirm.** `REQ-OUT-002` says the profiles use the HTTP destination by default; the profiles only set the delivery mode and the project passes adapters in code (ADR-013), so it is read as "it is the destination the core is built for". If a profile is meant to select it, that is a design change.
- **Choices.** A transient failure counts as `failed`, a permanent rejection as `dropped`, so the worker of T-05 can tell what to retry from the result alone; events below the minimum severity count as accepted and no request is made when nothing is left. The 12 settings are declared flat (Go cannot embed the client's struct in the canonical JSON). Go added `Limits`, `DefaultLimits` and `NewLimits` to `go/pkg/telemetry`, and Python exports `Limits`, so that a project can build the limits of a destination (an alias without a constructor is unusable: the zero value is invalid); `Limits` is now in the shared list of public names.
- **A flaky test fixed.** One run of the whole Go suite under load failed the TLS test of the shared client by a timeout (a 3 s timeout against a test certificate handshake on a loaded machine); the test now uses a 20 s timeout. The agent had seen it pass on re-runs.
- **Known gaps.** The destination does no queueing, batching or retry loop (T-05) and does not split a batch larger than the limit (the batcher uses `fits_in_batch`). A panic inside a value with a custom JSON marshaller is `destination_failed` in Go; the equivalent exception in Python is `serialization_failed` (the two cases are not in the shared fixtures). The Go race detector was not run (no cgo).
