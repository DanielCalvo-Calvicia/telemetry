## Goal

Provide a destination for audit events, once a project needs one. **Deferred until a project needs audit events** (Q06-6: the contract comes first and the adapter later).

## Design notes

- Nothing about the adapter is decided. When a project asks, the maintainer answers first: what must the project prove, where does it keep the events (a file, SQLite, an HTTP receiver, a service of its own), for how long, and who reads them.
- The most likely first adapter needs no new technology: the existing file or SQLite destination attached to the audit route of T-11.2. If that is enough, this task becomes only an example and a note, and no new adapter is written.
- If a new adapter is needed, it follows ADR-013: a module of its own in Go under `go/pkg/audit/<adapter>/` with its own `go.mod` and tag, an extra in Python, chosen by the project in code, no registration on import (REQ-ARC-013).
- It implements the audit port decided in T-11.2 and keeps the rules of ADR-005 and ADR-006.
- The documents keep saying that no destination of the library gives legal retention (T-11.3).

## Files

- `go/pkg/audit/<adapter>/go.mod` with its `external/`, `error/` and `helpers/` folders (the adapter name is fixed when the project asks)
- `python/src/telemetry/audit/<adapter>/` with the same folders, and its extra in `python/pyproject.toml`
- tests mirroring the code under the adapter's `internal/tests/` in Go and `python/internal/tests/`, with the fixtures of its destination
- the line of the adapter in `contracts/capabilities/registry.yaml`

## Acceptance criteria

- An audit event reaches the destination of the adapter and nothing else receives it.
- A failing destination never fails the caller and is visible in diagnostics.
- Importing the core alone does not download the dependencies of the adapter.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification
