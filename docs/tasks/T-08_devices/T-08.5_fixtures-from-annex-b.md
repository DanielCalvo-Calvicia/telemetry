## Goal

Turn the example events of Annex B of PR-001 into shared fixtures: each one validates against the schemas of T-08.1 and serializes to the same bytes in Go and in Python (REQ-CNF-005, REQ-CNF-006).

## Design notes

- The examples B.1 to B.7 are the source (Annex B, version 0.2). B.8 (a sensor every 50 ms) becomes a stream of readings built from B.1. The examples are illustrative and are corrected with the real projects in T-08.7 (Q04-7), so this task copies them as they stand and does not change their content.
- Each fixture has its input event and the expected canonical JSON (RFC 8785, T-02.5). The names, ids and values stay placeholders (public repository).
- Annex B follows the rules the tests check: `attributes` holds only scalars (flat keys), both times are UTC in the fixed format, `occurred_at` equals `observed_at` when the data carries it, and the `event_id` values are valid UUIDv7.
- Invalid fixtures: an attribute that is an object, a `quality` outside the enum, a `value` that is a list, `recorded_at` set by the consumer, a `kind` that is not registered.
- The fixtures use `digital_input`; if the maintainer drops it in T-08.1, B.2 changes in the same task and this task follows.
- The CI job that runs all fixtures through both languages is T-12.1; this task provides the device fixtures and the tests of each language.

## Acceptance criteria

- Every valid fixture validates against its schema in both languages and every invalid one is rejected with a classified error.
- For each valid fixture, Go and Python produce the same bytes as the `.canonical.json` file.
- The fixtures contain no secret, no internal host and no real name.
- Changing one byte of an expected file makes both tests fail.

Ends with the checks of the README section 3 green in every language the task names.
