## Goal

Correct Annex B, the device schemas, the enums and the list of helpers with what the real hardware needed, as the maintainer asked in Q04-7: the examples were written before any real project was looked at and are to be edited.

## Design notes

- The input is the result of T-08.6: which `kind` values, units, `quality` values, source keys and fields the real project used, and which ones the schemas lacked.
- A new value of an enum is a MINOR change of the contract (REQ-DEV-005, REQ-VER-003); a field that changes meaning is incompatible and needs a dated note and a new `schema_version` decision of the maintainer (REQ-VER-005).
- Annex B is a proposal text: the corrections are written as a dated note (`> **Update <date>:** ...`) plus the corrected examples, so the history stays readable. The fixtures of T-08.5 are regenerated from the corrected examples.
- The helper list of section 8.4 (REQ-DEV-011) changes only if the real project shows a source that is missing or one that is never used; a removed helper is removed from both languages.
- Names, ids and values stay placeholders: no real device name, host, serial number or location reaches this public repository.
- If a correction changes a decision, it gets an ADR (new or a dated update of ADR-011) with its row in `docs/README.md`.

## Acceptance criteria

- Every difference found in the pilot is either corrected in the documents, the schemas, the enums and the fixtures, or listed as rejected with its reason.
- The examples of Annex B, the schemas, the fixtures and the helpers agree with each other and validate in both languages.
- No document describes as built something that is not (planned stays planned).
- Every link of the changed documents resolves.
