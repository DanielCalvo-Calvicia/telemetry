## Goal

In Go and in Python: one typed helper per source, so the project that owns the hardware builds the same generic `device.*` event from the data specific to its source (REQ-DEV-011, REQ-DEV-012). The input differs per source; the output does not.

## Design notes

- The seven sources and their specific input (section 8.4): GPIO (pin, level, pull), I2C (bus, address, register), SPI (bus, chip select), serial (port, baud rate), camera (resolution, frame format), motor controller (motor id, speed, direction), generic vendor SDK (free `attributes`).
- A helper fills `kind`, `name`, `value`, `unit`, `quality`, `observed_at` and puts the source details in `attributes` as flat keys (REQ-CTR-010): `source_type` plus `<source>_<field>`, as in B.1 and B.2 of Annex B (`i2c_bus`, `gpio_pin`, ...). The keys of the other sources follow that pattern and are reviewed in T-08.7. Each helper stays far below the limit of 32 attributes.
- A helper never reads or drives hardware and imports no hardware library (REQ-DEV-012): an architecture test fails on such an import. Adding a helper changes no schema (REQ-DEV-004).
- The same helpers with the same names and fields in both languages (REQ-ARC-010).
- Helpers use the device sink port (`DeviceTelemetrySinkPort`, T-03.2) through the core service; they have no third-party dependency, so they live in the core and not in a module of their own.
- Questions to the maintainer:
  1. Which generic event does each helper produce? A sensor helper gives `device.measurement.recorded`; confirm that the motor controller gives `device.actuator.changed` and decide what the camera gives (a measurement with a `kind`, or a state).
  2. Placement of the public package: the proposal here is `go/pkg/device/<source>/` and `telemetry.device.<source>` in Python (REQ-ARC-012). Confirm.

## Acceptance criteria

- Each of the seven helpers produces a valid event whose `data` has the same fields for every source and whose source details are flat scalar keys in `attributes`.
- The same call in Go and in Python gives the same event.
- The core module and the Python package have no hardware library in their dependencies, and the architecture test fails on a planted import.
- The helper does not set `recorded_at`; `occurred_at` equals `observed_at` when it is given.

Ends with the checks of the README section 3 green in every language the task names.

## Verification

One table-driven test per helper in each language, schema validation of every output, the architecture test with a planted violation, a check of the dependency lists of `go.mod` and `pyproject.toml`.
