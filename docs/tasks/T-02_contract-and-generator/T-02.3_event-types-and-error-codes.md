## Goal

Create the registry of event types and the catalog of error codes, with the first entries, so the generator and the error model have a source.

## Design notes

- Event types are `domain.entity.action` (REQ-CTR-001), each with a JSON schema of its `data` under `contracts/schemas/` (REQ-CTR-002). Each event type is added together with its capability (Q02-5: one at a time); this task creates the registry and the first type, `log.entry.recorded` (REQ-LOG-007, Q02-4): `data` holds the category, the function and the message, and the application goes to `resource.service_name`.
- The schema of `log.entry.recorded` keeps what the old `Entry` has (category, function, message; call context in `context`) and adds nothing that the old library did not carry. Its severity comes from the envelope.
- Error codes (REQ-CNF-004): one catalog shared by both languages, with a stable code, a category and a default message. Message text may vary per language; codes may not. This task writes the validation and configuration codes (an event that fails its schema, an unknown event type, a limit exceeded, an invalid configuration field, an unknown delivery mode).
- The failure classification of REQ-FLT-001 (code, category, severity, recoverable or not) is defined in the contract here as a schema and an enum only; its use (`fault.*` events) belongs to T-07.3. Open question to the maintainer: does the catalog of error codes also hold the delivery failure codes now, or does each capability add its own as it is built (the plan says the latter for event types)? Default if unanswered: each capability adds its own.
- Where the registry and the catalog live is the open question of T-02.1 (proposal: `contracts/events/registry.yaml`, `contracts/errors/catalog.yaml`).
- The old sentinels (`application/errors.go`, `domain/errors.go`) are not read: the new ones are written in T-03.7 from this catalog.

## Acceptance criteria

- Every registered event type points to an existing schema, and every schema file is registered (a check run by the generator in T-02.4).
- Every error code is unique, written in `snake_case` or the pattern the catalog documents, and has a category.
- A sample `log.entry.recorded` event with category, function and message validates; one without a message is rejected.
- The failure classification has the four fields of REQ-FLT-001.
- The open questions above are answered or listed as open in the folder README.
