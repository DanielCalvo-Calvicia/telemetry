## Goal

Create the first events with their expected canonical JSON, and make both languages run them (REQ-CNF-005).

## Design notes

- `integration-tests/fixtures/` holds files that both implementations read; neither language owns them. Each case is an input event (as a structured document), the expected canonical bytes and, for invalid cases, the expected error code.
- First cases: a minimal envelope; a full envelope (resource with `time_zone`, actor, context, attributes); a `log.entry.recorded` event; the same logical event written with keys in another order; two times with trailing zeros (`.120000Z`); a time with a non-UTC offset (rejected); a string with characters outside the Basic Multilingual Plane; a number table (the one of T-02.5). Placeholders only: names like `sensor-hub`, ids like `hub-01`; no real host or customer.
- The examples of Annex B of PR-001 are not fixtures yet: they become fixtures in T-08.5, after the device schemas exist.
- A fixture is a change of the contract if it changes bytes already written: a new case is added, an existing expected value is changed only with the same pull request and dated ADR note as a contract change (Q01-4).
- Each language has a thin test that loads the folder, serializes every valid case and compares the bytes, then checks that invalid cases return the expected error code (T-02.6). The cross comparison of the two languages with each other is T-12.1.
- The files are data, so the coverage of the fixtures is not measured.

## Acceptance criteria

- Every valid fixture serializes to its expected bytes in Go and in Python, and the bytes are compared exactly, not as parsed JSON.
- Every invalid fixture returns the expected error code in both languages.
- Adding a fixture file needs no code change in either test (the tests read the folder).
- No fixture contains a real host, address, secret or customer name.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Run the fixture test in `go/` and in `python/`; change one expected byte on purpose to see both fail, then revert it.

## Notes

**Done 2026-10-29** (Go 1.25.5, Python 3.11.1, Node 22.19). Done by the coordinator without an agent: the task is small.

- **What was built.** The folder `integration-tests/fixtures/` with a README that defines the case format (`kind`: `canonical`, `time` or `validation`; `input`; `expected` or `error_code`; `message_contains`); 6 envelope cases and 4 event cases; the thin tests `go/internal/tests/contract/fixtures_test.go` and `python/internal/tests/contract/test_fixtures.py`, which read the folders `envelope/` and `events/`. The two tables of T-02.5 and T-02.6 (`canonical_json/`, `event_validation/`) moved here with `git mv`, and the four path constants and the comparison script were updated.
- **The cases.** A minimal envelope; a full envelope (resource with `time_zone`, actor, context, attributes); the same logical event with every key order reversed (identical bytes); times with trailing zeros kept (`.120000Z`); a three-decimal input formatted to six; a time with a `+02:00` offset (rejected, `event_schema_invalid`); a `log.entry.recorded` event with characters outside ASCII and the BMP; attribute keys outside the BMP, sorted by UTF-16 code units; a `log.entry.recorded` without its message (rejected); an unknown event type (rejected, `event_type_unknown`).
- **The expected bytes do not come from the implementation under test.** They were computed with Node.js (`JSON.stringify` is the ECMAScript serialization RFC 8785 is defined on; keys sorted by UTF-16 code units). Both languages reproduce them exactly.
- **Verification.** All 10 cases pass in Go and in Python. **One expected digit changed on purpose** in `envelope/full.json` makes both tests fail; reverted, both pass. **A new fixture file added with no code change** runs in both languages (then removed). Go: `gofmt` and `goimports` clean, vet and build clean, tests pass, coverage **99.0%**. Python: `ruff` clean, **69 tests**, coverage **100%**. The canonical JSON comparison still gives `2 of 2 cases are identical in Go and Python`. The registry check passes with `REQ-CNF-005` now covered by tests (11 of 130 covered, 111 pending, 8 without a task).
- **Choices.** A `time` case gives an ISO text with an explicit offset, because a fixture is JSON and the formatter takes an instant; the offsets use three or six decimals so Python 3.10 can parse them. A fixture whose kind is unknown fails the test, so a typo is never skipped. The architecture fixtures (planted violations) stay with the Go tests: they are not shared. The files are data, so their coverage is not measured.
- **Left for later.** The examples of Annex B become fixtures in T-08.5; the runner that compares the two languages in CI is T-12.1 (the CI job `cross-tests` is still empty).
