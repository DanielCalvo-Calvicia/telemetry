## Goal

A small Go program that reads `contracts/` and writes the code of both languages, with a CI job that fails when the committed output differs.

## Design notes

- Q02-3: one small generator in this repository, written in Go, that emits both languages. REQ-CNF-002 and REQ-DST-005: it emits enums, event types, error codes, envelope types and the configuration schema, the output is committed, and a Python install never needs Go.
- The generator is deterministic: sorted input, no timestamp or machine path in the output, a header "generated, do not edit" naming the source file. Running it twice gives the same bytes.
- It also checks the contract before generating: every schema is valid JSON Schema, every registered event type has its schema and the other way round, error codes are unique, enum values are unique.
- Decided by the maintainer on 2026-10-28: the program lives in a module of its own, `tools/contract_generator/` (option B), so the core keeps a minimal dependency set (REQ-ARC-005). The tool entry point `main.go` is allowed: the `CLAUDE.md` rule "no `cmd/`" is about the library.
- Decided by the maintainer on 2026-10-28: the generated code lives in the domain layer, `go/internal/domain/value_objects/*_generated.go` and `python/src/telemetry/internal/domain/value_objects/*_generated.py`. The configuration schema feeds T-03.6 and is not generated yet.
- Go names follow `PascalCase` and Python names follow the rule of `contracts/conventions/naming.md`; JSON stays `snake_case`.

## Acceptance criteria

- One command regenerates both languages; a second run changes nothing.
- On a fixture contract the output equals the expected files byte by byte.
- Changing a schema or an enum without regenerating makes the CI job fail; regenerating makes it pass.
- A broken contract (a schema with no event type, a duplicated code) stops the generator with a message that names the file.
- The generated Python imports with no third-party package and no Go.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Tests of the generator on the fixture contract; the drift check run locally (`git diff --exit-code` after generating); an import test of the generated Python module in `python/internal/tests/contract/`.

## Notes

**Done 2026-10-28** (Go 1.25.5, Python 3.11.1, Windows). The code was written by a delegated agent from a precise brief and then **verified independently** by the coordinator (the numbers below are the coordinator's).

- **What was built.** `tools/contract_generator/` (its own module, listed in `go.work`; `go.mod`, `go.sum`, `main.go`, `README.md`): `internal/domain` (the model, the naming and `Contract.Validate()`), `internal/application` (the ports `ContractReader`, `CodeRenderer` and `FileWriter`, the use case and the sentinels), `internal/infrastructure` (the command line, the contract-folder reader, the Go and Python renderers, the file writer; the I/O in `external/` folders) and `internal/composition_root`. Third-party libraries, only in this module: `gopkg.in/yaml.v3` and `github.com/santhosh-tekuri/jsonschema/v6`. `go.work.sum` was created by Go and is committed. The generated code: 4 Go files and 4 Python files (`enums`, `event_types`, `error_codes`, `envelope`, each `_generated`) plus a hand-written `python/.../value_objects/__init__.py`.
- **The check before generating.** It reports every breach with the file: a schema that is not valid JSON or not a valid 2020-12 schema, an unresolved `$ref`, a registered type with no schema, a schema that is not registered, a duplicated or malformed error code, an unknown category, a duplicated enum value (also ignoring case), a duplicated event type. If it fails nothing is written. Example: removing `entry_recorded.schema.json` gives `registered event type without a schema: contracts/events/registry.yaml: "log.entry.recorded" has no contracts/schemas/log/entry_recorded.schema.json`.
- **Tests.** Black-box, mirroring the code, under `tools/contract_generator/internal/tests/`: a fixture contract whose Go and Python output equals the golden files byte by byte (`*.go.golden`, `*.py.golden`, so the Go tool never compiles them), the second run, and the broken contracts (all listed above plus bad enum values, event types and error codes, a schema path mismatch, a missing message, unsupported constructs, invalid YAML and a missing registry or catalog). Also a Go test of the generated functions in `go/internal/tests/contract/` and a Python test in `python/internal/tests/contract/test_generated_imports.py`.
- **Verification (coordinator, 2026-10-28).** `gofmt -l` and `goimports -l` print nothing in `tools/contract_generator` and `go/`; `go vet`, `go build` and the tests pass in both; coverage without `external/` is **98.1%** for the generator (8 test packages) and **98.7%** for `go/` (gate 95%); the real generation runs twice and all **8 generated files are byte-identical** after the second run; `ruff check` and `ruff format --check` pass; the Python tests (20) pass with **100%** coverage (79 statements); the generated Python imports with no third-party package. **The drift check:** adding an actor kind to `contracts/enums/actor_kind.json` changes the generated output, and restoring it and regenerating gives the original output back, so a stale committed copy differs and the `generated-code` job fails, and regenerating makes it pass (the job itself runs only on GitHub).
- **CI.** The job `generated-code` runs the generator and fails on `git diff --exit-code` or on a new file. The `go` job matrix includes the generator module automatically because it is in `go.work`. `pyproject.toml` excludes `*_generated.py` from ruff.
- **Design choices to know.** (1) Go field names are the mechanical form of the naming rule (`EventId`, `TraceId`), not Go's `ID` style; `golint`-style checkers would complain. (2) An optional number, integer or boolean is a pointer in Go, so `omitempty` does not drop `false` or `0`; the current contracts have none, the fixture does. (3) The Python dataclasses are not frozen (except `ErrorCodeInfo`), in case T-03 builds them step by step. (4) Required fields come first, then optional ones, each alphabetical, in both languages. (5) The generated Python imports its sibling modules with the absolute path `telemetry.internal.domain.value_objects...` because the repository forbids relative imports. (6) The generator understands a subset of JSON Schema (see its README) and fails clearly on anything else.
- **Not generated.** The configuration schema (REQ-CNF-002): it does not exist until T-03.6.
- **Left for later.** The canonical JSON serialization is T-02.5; validation at the source is T-02.6; the check of the capabilities registry is T-02.7; fixtures are T-02.8.
