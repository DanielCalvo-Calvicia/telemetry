## Goal

Write the JSON Schema of the event envelope and the severity enum, the base every event of every capability uses.

## Design notes

- Fields of REQ-CTR-001: `schema_version`, `event_id`, `event_type`, `occurred_at`, `recorded_at`, `severity`, `resource`, `actor`, `context`, `data`, `attributes`. Required: all but `actor`, `context` and `attributes`. `data` is required and may be empty.
- `resource` (section 5.2): `service_name` and `instance_id` required; `environment`, `service_version`, `host` and `time_zone` optional. `time_zone` is an IANA name, for display only and never used to compute a time (ADR-012, Q09-1). `actor`: `kind` and `id` required, `type` and `version` optional; `kind` comes from `contracts/enums/`. `context`: `trace_id`, `span_id`, `execution_id`, `correlation_id`.
- Times: `occurred_at` and `recorded_at` are UTC with the fixed format `YYYY-MM-DDTHH:MM:SS.ffffffZ` (REQ-CNF-003, REQ-CTR-008). `recorded_at` is set only by the library; the schema documents that, the code enforces it in T-03.3.
- `event_id` is a UUIDv7 (REQ-CTR-009, Q02-2). `schema_version` is `MAJOR.MINOR` and starts at `0.1` (Q02-6).
- Severity values: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`, `CRITICAL`; `contracts/enums/severity.md` says what each means and how it maps to `log/slog`, Python `logging` and OpenTelemetry (section 5.3).
- Limits of REQ-CTR-010 (32 attribute keys, key 64, value 256, scalars and lists of scalars only) are written in the schema of `attributes`; the size limit of the whole event (64 KiB) is a rule for T-03.5 and is noted, not a schema keyword. Consumers ignore unknown fields of later MINOR versions (REQ-VER-004), so the schema keeps `additionalProperties` open only where the plan allows.
- The generic `data` schema is an open object; each `event_type` narrows it (T-02.3).

## Acceptance criteria

- The schemas are valid JSON Schema documents and validate themselves (the check of T-02.4 loads them).
- A sample envelope with every field validates; one without `occurred_at`, with a lowercase severity, with a time that is not UTC `Z` or with a nested value in `attributes` is rejected.
- `severity.md` covers the six values and the three mappings.
- No field is described twice: each concept has one field (section 5.2).

## Notes

**Done 2026-10-28.** Data and documentation only; the check ran with the `jsonschema` library in a throwaway virtual environment (nothing was added to the repository).

- **What was built.** `contracts/schemas/envelope.schema.json` and `common/{resource,actor,context,attributes}.schema.json`; `contracts/enums/severity.json`, `severity.md` and `actor_kind.json`; the READMEs of `schemas/` and `enums/`. The dialect is JSON Schema draft 2020-12. The files are `.json` written with two-space indentation.
- **Enums are schemas too.** `severity.json` and `actor_kind.json` are small JSON Schema documents with an `enum`, so the envelope and `actor` `$ref` them and the generator (T-02.4) reads the same file.
- **Placeholder `$id`.** The identifiers and references use `https://telemetry.example/contracts/...`, a placeholder (the `.example` domain is reserved): nothing is fetched from it, the schemas are resolved from the folder.
- **A choice made here, confirmed by the maintainer on 2026-10-28.** The objects are **closed** (`additionalProperties: false`): a producer never emits a field the contract does not name, and the extension point is `attributes`. A consumer is tolerant and ignores the unknown fields of later MINOR versions (REQ-VER-004); that is a rule of how it reads, not a schema keyword. The plan said to keep the schema open "only where the plan allows"; `data` and `attributes` are the open places.
- **Details chosen from the plan.** `event_id` is a lowercase UUIDv7 (the version digit 7 and the variant 8 to b are checked); `event_type` is exactly three lowercase segments; the times need exactly six decimals and the zone `Z`; `trace_id` is 32 and `span_id` 16 lowercase hexadecimal digits (W3C); `time_zone` is a name made of letters, digits, `_`, `+`, `-` and `/` (it does not check the name against the IANA database). Attribute values are strings up to 256 characters, numbers or booleans, or lists of those (no `null`, no nesting).
- **Not in the schema.** The size limit of a whole event (64 KiB) is a rule of the library (T-03.5). `format: date-time` was not used, because the pattern is stricter. The schema cannot say that only the library sets `recorded_at`; it says so in the description and T-03.3 enforces it.
- **Verification.** Each of the 7 files is a valid 2020-12 document (`check_schema`); a fully populated envelope and a minimal one validate; **28 invalid samples are rejected**, one or more per rule: a missing `occurred_at`, `recorded_at` or `data`, a lowercase or unknown severity, a time with an offset, with three decimals or with none, a nested object, a list of lists or a `null` in `attributes`, 33 attributes, a key of 65 characters, a value of 257, a UUIDv4 or uppercase `event_id`, an `event_type` with two segments or in uppercase, a `schema_version` without a minor, an unknown top-level field, a resource without `instance_id` or with an unknown field, a time zone with a space, an actor of an unknown kind or without `id`, an uppercase `trace_id`, a short `span_id`, and a `data` that is not an object. The 8 example events of Annex B of PR-001 validate against the envelope.
- **`severity.md`.** The six values with their meaning and the mapping to `log/slog` (`TRACE` and `CRITICAL` are custom levels), Python `logging` (`TRACE` is a custom level) and OpenTelemetry (`CRITICAL` is `FATAL`).
- **Left for later.** The schema of each event type (T-02.3 and the capabilities); the check that loads and runs these schemas is T-02.4; the fixtures with these samples are T-02.8.
