## Goal

Serialize an event to the same bytes in Go and in Python, using the JSON Canonicalization Scheme.

## Design notes

- REQ-CNF-003 and REQ-CTR-004: byte-for-byte identical JSON for the same logical event, by RFC 8785 (JCS): keys sorted by UTF-16 code units, no insignificant whitespace, strings escaped by the rule of the RFC, numbers in the ECMAScript form.
- Times use the fixed format `YYYY-MM-DDTHH:MM:SS.ffffffZ`: UTC, six decimals, always the `Z`, trailing zeros kept (ADR-012). A function formats an instant and rejects a non-UTC value with a classified error. Go keeps nanoseconds in `time.Time` and Python keeps microseconds in `datetime`: both truncate (not round) to microseconds.
- Numbers are the hard part: Go and Python print floats differently. The canonical form of a double is the shortest round-trip form of the ECMAScript algorithm. Write it once per language and test both against the same table of values (integers, `1e21`, `0.000001`, `-0`, the largest safe integer). Integers beyond 2^53 are an open question: reject them in the contract or serialize them as strings? The maintainer did not answer (the question was declined on 2026-10-28), so the plan's default is used: the serializer rejects them with a classified error. It is one constant per language, so changing it is small.
- No third-party library in the core (REQ-ARC-005): each language implements JCS with its standard library. The serializer is a pure function of the domain layer (`operations/`), without I/O.
- The Go function is `CanonicalJSON(event)` and the Python one is `canonical_json(event)` (naming rule of T-02.1); both live in the same-named folder `domain/operations/canonical_json/`.
- Private fields never reach the output; `recorded_at` is already set by then (T-03.3).

## Acceptance criteria

- The test vectors of RFC 8785 (the sorting, string escapes and number examples of the RFC) pass in both languages.
- The same event gives identical bytes in Go and Python on the fixtures; key order in the input never changes the output.
- `occurred_at` and `recorded_at` always have six decimals and the `Z`; a non-UTC instant is rejected, not converted silently.
- Characters outside the Basic Multilingual Plane sort by UTF-16 code units in both languages (a fixture covers it).
- Ends with the checks of the README section 3 green in every language the task names.

## Notes

**Done 2026-10-28** (Go 1.25.5, Python 3.11.1, Node 22.19 for the independent check). The code was written by a delegated agent from a precise brief and then **verified independently** by the coordinator (the numbers below are the coordinator's).

- **What was built.** Go: `go/internal/domain/operations/canonical_json/{canonical_json,number_format,time_format}.go` and `go/internal/domain/errors.go`. Python: `python/src/telemetry/internal/domain/operations/canonical_json/{canonical_json,number_format,time_format}.py` and `python/src/telemetry/internal/domain/errors.py`. Tests under `go/internal/tests/domain/operations/canonical_json/` and `python/internal/tests/domain/operations/canonical_json/`; the four shared fixture tables; `integration-tests/compare_canonical_json.py`. The format is described in the architecture document, section 2.5.
- **The open question, default used.** Integers beyond ±2^53-1 are rejected with `limit_exceeded` (the maintainer declined the question). `MaxExactInteger` (Go) and `MAX_EXACT_INTEGER` (Python) are the only place to change; "integers as strings" would change `FormatInt` and `format_int`. A double such as `1e20` still prints in full, and the RFC row `9007199254740992` passes as a float.
- **Error codes.** An integer out of range: `limit_exceeded`. NaN or an infinity, a non-UTC instant, an unsupported value type and a string with a lone surrogate or invalid UTF-8: `event_schema_invalid`.
- **The test vectors, and a caveat found on the way.** The agent could not read the text of RFC 8785 (the fetch returned only a summary), so it typed the vectors of Appendix B, the sorting example and the string-escape example **from memory**. The coordinator therefore checked all of them independently with Node.js, whose `JSON.stringify` is the ECMAScript serialization the RFC is defined on and whose key sort is by UTF-16 code units: **all 85 fixture cases agree** (51 numbers, 24 strings, 8 sorting, 2 events). One recalled value was wrong and the agent had corrected it by computing: `becbf647612f3696` is `-0.0000033333333333333333`, not `...35`. The vectors were not compared with the RFC text itself; do that when the text is at hand.
- **Verification (coordinator).** Go, inside `go/`: `gofmt -l` and `goimports -l` print nothing; `go vet`, `go build` and `go test` pass; coverage without `external/` is **98.6%**; the architecture tests stay green (the new code imports only the standard library and the domain). Python in a clean environment: **46 tests**, `ruff check` and `ruff format --check` pass, coverage **100%** (188 statements). **Byte comparison:** `python integration-tests/compare_canonical_json.py` prints `2 of 2 cases are identical in Go and Python` (the minimal event, 338 bytes, and the fully populated one, 879 bytes); each case compares Go, the Python dict, the Python generated `Envelope` dataclass and the expected text. The generated files are unchanged.
- **Design choices.** The Go function walks the value with `reflect` and honours the `json` tags instead of marshalling and decoding, so an int and a float stay different (Go `float64(1e20)` and Python `1e20` give the same bytes); a type with its own `MarshalJSON` or `MarshalText` goes through `json.Marshal` and is rewritten canonically; embedded structs and `[]byte` are rejected. Python takes the digits from `repr(float)` and uses the same layout function as Go; keys are sorted by their UTF-16 big-endian bytes. The Python tests read the Go fixture files (one copy, so they cannot drift; a missing file fails the tests).
- **Defects and open points for T-03 (not fixed here).** (1) The Go `Envelope.Data` is `map[string]any` without `omitempty`, so a nil map prints `"data":null` while Python `data={}` prints `{}`; the builder of T-03.3 must always give a non-nil `data`. (2) Go `omitempty` cannot tell unset from empty for `""` or an empty `Attributes` map (both are omitted), while Python omits only `None` (so `environment=""` prints `""`); the fixtures avoid it and T-03.1 needs a rule (for example that the schema forbids empty strings, which it already does for `resource`). (3) `attributes` is `map[string]any`, so the type of a number in it depends on the caller. (4) `domain/errors.go` imports `value_objects` only for the codes; T-03.7 may move it. (5) The CI job `cross-tests` does not run the comparison script yet (T-12.1).
- **Left for later.** The fixtures move to `integration-tests/fixtures/` in T-02.8; validation at the source is T-02.6.
- **Moved by T-02.8 (2026-10-29).** The shared fixtures of this task are now in `integration-tests/fixtures/` (`canonical_json/`, `event_validation/`); the paths above were updated and the tests read them from there.
