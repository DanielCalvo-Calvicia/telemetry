## Goal

Create the folders of the contract and write the naming rule, so every later schema has a place and a name.

## Design notes

- Folders required by the plan: `schemas/`, `enums/`, `capabilities/registry.yaml`, `conventions/naming.md` and `storage/` (the layout of the SQLite destination, REQ-OUT-009, Q09-5: a reader only reads). Device and AI schemas will live in `schemas/device/` and `schemas/ai/` and their enums in `enums/device/` and `enums/ai/` (REQ-DEV-002, REQ-AI-001).
- `naming.md` holds the mechanical rule of REQ-ARC-010: Go exported identifiers in `PascalCase`; Python `snake_case` for functions and `PascalCase` for classes; JSON fields `snake_case` in both (Go struct tags do the mapping; Q02-7). A concept is never renamed in one language. Event types are `domain.entity.action` (REQ-CTR-001).
- Decided by the maintainer on 2026-10-28: the registry of event types lives in `contracts/events/`, the catalog of error codes in `contracts/errors/` and the configuration schema in `contracts/config/` (T-02.3 and T-02.4 use them).
- The Python names of the public packages were confirmed in T-01.1 (2026-10-28) and are in `naming.md`.
- Every file is documentation or data: no code here. The folder README says that only the maintainer approves a change by pull request and a dated note in an ADR (Q01-4).
- No secrets, no internal hosts; examples use placeholders.

## Acceptance criteria

- `contracts/` has the five folders of the plan, each with a file that explains it.
- `naming.md` states the three rules and gives one worked example per language, using the event `log.entry.recorded`.
- The open question about events, errors and configuration is answered by the maintainer and the layout follows the answer, or it is listed as open in the folder README.
- Every link in the new files resolves; no file contains a secret or a real host.

## Notes

**Done 2026-10-28.** Documentation and data only; no code.

- **What was built.** `contracts/` with eight folders, each with a README (`schemas/`, `enums/`, `events/`, `errors/`, `config/`, `storage/`; `capabilities/registry.yaml` and `conventions/naming.md` are their own files) and the top README (the folders, who fills each, how a change is made, the state). `registry.yaml` holds a header that explains the future entries and `capabilities: []`; it parses as YAML.
- **The decision.** The three extra folders (`events/`, `errors/`, `config/`) are the maintainer's answer of 2026-10-28; the plan had five folders.
- **`naming.md`.** The three rules (Go, Python, JSON), a table that derives each name from its words and a worked example of `log.entry.recorded` in JSON, Go and Python; the public packages (`go/pkg/telemetry`, `telemetry.<functionality>.<adapter>`) and what T-12.3 will check. The `LogEntryRecorded` snippets illustrate the rule; the real types are generated by T-02.4.
- **Documents.** README layout, architecture (section 2.3), `requirements.md` (REQ-ARC-010 and REQ-CNF-001), a pointer in `docs/api/api.md`, the T-02.3 note that said the layout was an open question.
