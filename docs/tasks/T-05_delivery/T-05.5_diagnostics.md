## Goal

Let the consumer see how delivery is doing, per destination, without a failure of the library creating events that fail again (REQ-DGN-001 to REQ-DGN-003).

## Design notes

- Per destination: queue depth, drops by reason, export failures, retries, export latency, batch size, spool use and quota, last successful send, configuration errors, serialization failures and the result of the last flush (REQ-DGN-001). Spool figures stay at zero until T-06.5.
- Two ways to read it (REQ-DGN-002): a snapshot function that returns a copy, and optional callbacks the consumer registers. A callback that fails or is slow must not break the worker; it runs outside the send path.
- An internal channel with its own rate limit, so a failure of telemetry never produces an event that goes through the normal path and can fail again (REQ-DGN-003). The rate limit value is not in PR-001: question to the maintainer.
- Open point for the maintainer: ADR-005 sends an ERROR entry to a fallback sink (the console) when a sink fails. Does the diagnostics channel replace that fallback, or does the console stay as a destination of the diagnostics?
- Diagnostics carry counters and identifiers, never the message or the fields of an event (they may be sensitive, ADR-005) and never a credential (REQ-SEC-007).
- The drop reasons are the ones of T-05.2 and the failure classes those of T-04.4; one list in `contracts/enums/` keeps the names equal in Go and Python (REQ-CNF-001).
- Diagnostics are not a health signal: a failing exporter does not mark the application unhealthy (REQ-HLT-003, T-07.4).

## Acceptance criteria

- A scenario with drops, failures, retries and a flush gives the expected value for each counter of REQ-DGN-001, in both languages.
- The snapshot is a copy: changing it does not change the library.
- A callback that raises or hangs does not affect delivery.
- A failing diagnostics callback produces no new telemetry event, and the channel's rate limit holds under a storm of failures.
- No diagnostic holds an event message, a field value or a token.

Ends with the checks of the README section 3 green in every language the task names.

## Verification

Tests with fake destinations that fail in each way; a test of the rate limit with a fake clock; a test that searches the snapshot and the callback payloads for a known secret and a known message and finds neither.
