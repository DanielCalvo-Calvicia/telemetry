## Goal

Give each destination one delivery mode and implement the two in-memory ones (section 10.1). `durable` is T-06.5.

## Design notes

- `best_effort`: a bounded queue and no guarantee beyond not blocking the caller. `retry`: the same queue, with retries and backoff up to a limit. Neither survives a process restart.
- The mode of each profile is the one of REQ-CFG-004: `best_effort` for `microservice`, `retry` for `cronjob` and `worker`, and `durable` for `robotics` and `offline_device`. The profiles are written in T-03.6; this task reads the mode from the configuration and a test checks that each profile reaches the right behavior. A `durable` destination before T-06.5 is not available: asking for it is a configuration error that says so.
- Retry uses the policy of T-04.4 (exponential backoff with jitter, `Retry-After`) and the classes of 10.6: transient failures are retried, a permanent rejection (4xx except 408 and 429) is not.
- Open points for the maintainer: the retry limit (attempts or total time) and the first backoff and its cap have no value in PR-001; and 10.6 says a permanent rejection is "dropped or set aside": in this epic it is dropped and counted, unless the maintainer wants a place to set it aside.
- The result is reported as delivered only after the destination confirms it (REQ-DLV-003). An event retried after a timeout may arrive twice; `event_id` lets the receiver deduplicate (REQ-DLV-001, Q03-7). The library does not claim exactly-once.
- While a batch is being retried, new events keep entering the queue under the policy of T-05.2.
- The retry of one destination never delays another (REQ-DLV-005).

## Acceptance criteria

- With `best_effort` a failed batch is not resent beyond the documented behavior; with `retry` a batch that fails twice with 5xx and then succeeds is delivered once and counted as delivered only at the third answer.
- A 4xx other than 408 and 429 is not retried.
- When the retry limit is reached the batch is dropped and counted.
- Each profile gives its mode from REQ-CFG-004.
- Backoff delays grow and carry jitter; with a fake random source they are equal in both languages.

Ends with the checks of the README section 3 green in every language the task names.
