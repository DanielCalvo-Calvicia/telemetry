## Goal

In Python (an extra): the same as T-09.7 for LlamaIndex, and "not applicable" in Go in the capabilities registry (REQ-AI-009, REQ-AI-011).

## Design notes

- The adapter hooks into the instrumentation or callback mechanism of LlamaIndex and calls the generic callbacks of T-09.2. It adds no event type and no schema (REQ-AI-003). Its place is `outbound/ai_runtime/llamaindex/` (REQ-AI-009), in Python `python/src/telemetry/ai_runtime/llamaindex/`.
- It follows the same rules as T-09.7: an extra, no import from the core, metadata only by default (T-09.3), tests with fake models and no network, Go marked "not applicable" (REQ-AI-011).
- Q05-2 asks for the framework to exist even before a project uses it; Q07-14 makes it Python only.
- A query that retrieves documents is not recorded as a document dump: retrieved content follows the content switch of T-09.3.
- Questions to the maintainer:
  1. Which LlamaIndex versions must be supported? Nothing in the answers names one.
  2. Which operations of LlamaIndex must be visible: model calls and tool calls only, or also retrieval and query steps? The nine event types of section 9.2 have no retrieval event; a retrieval step would be an execution or an `attributes` entry, to be decided.

## Acceptance criteria

- A query with a fake model and a fake tool produces `ai.model.*` and `ai.tool.*` events that validate against the schemas.
- An exception in the framework is reported and re-raised unchanged.
- Installing the package without the extra does not install LlamaIndex; importing the core never imports it.
- The registry shows Go as "not applicable" and the registry check passes.
- Retrieved text does not appear in any event unless the content switch is on.

Ends with the checks of the README section 3 green in every language the task names.
