## Goal

In Python: the existing agent that already uses Langfuse (Q05-1) uses the library instead of its own recording, and the maintainer checks one run. **Needs the maintainer.**

## Design notes

- The agent is a Python project outside this repository. The changes inside it are made in its own repository; here the repository gets a smoke test with a fake agent that repeats the calls of the pilot, and the record of the run.
- What the agent does today and must keep: model calls, tool calls, hand-offs, approvals and policy denials (Q05-6: "they already exist"). They are reported through `ai.*` events, with the agent as an `actor` with `kind=agent` and its runs as executions (T-07.2).
- Only metadata unless the maintainer switches more on (Q05-4, T-09.3). A prompt or a tool result must not appear in the first run.
- Langfuse receives the events through the adapter of T-09.6 and the result is compared with what the agent's own recording showed before.
- Offline or failing destinations do not stop the agent: the delivery mode `durable` of T-06.5 keeps events in the spool.
- Names, hosts, keys and project ids stay out of the repository (public repository): placeholders only.
- Questions to the maintainer:
  1. Which framework does the agent use? If it uses LangChain or LlamaIndex, T-09.7 or T-09.8 take part in the run; Q05-1 does not say.
  2. What does the agent's own recording capture today that the nine event types do not (so it can be listed, kept in `attributes`, or dropped)?
  3. When can the maintainer run the agent for the check?

## Acceptance criteria

- The smoke test passes: model calls, tool calls, a hand-off, an approval and a denial reach the fake destinations.
- On a real run, the maintainer confirms that the agent reports the same facts as before, through the library, and that Langfuse shows them.
- No prompt, tool result or image appears unless a switch is on.
- A failing destination does not stop the agent.
- The agent no longer needs its own recording code for these events.

Ends with the checks of the README section 3 green in every language the task names.
