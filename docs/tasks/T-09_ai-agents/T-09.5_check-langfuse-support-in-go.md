## Goal

Find out how Go will talk to Langfuse and write the result as an ADR, before the adapter is built (D-09, REQ-AI-010).

## Question

Does Go have a usable Langfuse SDK, or must the Go adapter use the HTTP or OTLP API of Langfuse? In detail:

1. Is there an official Go SDK, and is it maintained and compatible with the Go version of the library (Go >= 1.25)?
2. If not, which API is used: the OTLP endpoint or the ingestion API over HTTP? How are the `ai.*` events mapped to traces, generations, spans and events of Langfuse?
3. How are the credentials supplied? They come from the consumer's configuration, never from a file or the environment of the library (ADR-004), and no key reaches this public repository.
4. Which Langfuse versions are supported, and is the URL always taken from the configuration, whether the service is hosted by the vendor or self-hosted?
5. Can the Python SDK and the Go API give the same observable result (REQ-AI-010)? Where they cannot, what is the documented difference?

## Resolution

Not taken yet. The answer of the maintainer is in [Q07](../../setup/questionnaires/Q07_open-points-after-the-answers.md), question 15: the check is done when the AI work starts and its result is written as an ADR; the original default of [Q05](../../setup/questionnaires/Q05_ai-agents-and-langfuse.md), question 3, is the SDK in Python and the HTTP or OTLP API in Go. The check must read the current Langfuse documentation at that time. The maintainer accepts the ADR.
