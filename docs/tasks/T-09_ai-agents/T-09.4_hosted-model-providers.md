## Goal

In Go and in Python: capture the usage, the duration and the normalized errors of the calls an agent makes to hosted model providers, as events `ai.model.*` (REQ-AI-009, REQ-AI-012).

## Design notes

- There is no schema per provider (REQ-AI-003): the adapter only fills `provider`, `model`, `usage`, `duration_ms` and `error` of the generic events.
- Durations are measured with a monotonic clock (REQ-CTR-008), never with wall-clock time.
- Normalized errors: the adapter maps what a provider returns (rate limit, timeout, invalid request, server error) to the `code`, `category` and `retryable` of `ai.model.failed`. The mapping is a data table in `helpers/` with the category values of T-09.1; it contains no provider-specific branch in the domain.
- Usage is token counts only (REQ-AI-012); a provider that returns a cost has it ignored.
- A third-party SDK of a provider is installed separately (REQ-DST-004). This adapter must not make the core depend on one.
- Questions to the maintainer (the source of the plan names no provider):
  1. Which hosted providers must be covered first?
  2. The adapter wraps the consumer's own call through a function the consumer passes in (no provider dependency), or is there one adapter per provider, each with its own module in Go and its own extra in Python?
  3. Is the call recorded for streaming responses, and with which duration (first token or last)?

## Acceptance criteria

- A successful call gives `ai.model.invoked` and `ai.model.completed` with usage and duration; a failed call gives `ai.model.failed` with the normalized error.
- Each error class of the mapping table gives the expected `category` and `retryable` value in both languages.
- A provider that returns a cost produces an event with no cost.
- The core has no provider SDK among its dependencies.
- A failing sink never raises into the caller's model call.

Ends with the checks of the README section 3 green in every language the task names.
