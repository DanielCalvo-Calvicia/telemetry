## Goal

Write the nine `ai.*` schemas and the AI enums in `contracts/`, so the generator (T-02.4) gives both languages the same types (REQ-AI-001 to REQ-AI-005). The task is a contract and has no language of its own; the generated Go and Python code is checked by both.

## Design notes

- The nine event types of section 9.2: `ai.model.invoked`, `ai.model.completed`, `ai.model.failed`, `ai.tool.called`, `ai.tool.completed`, `ai.agent.handoff`, `ai.approval.requested`, `ai.approval.resolved`, `ai.policy.denied`. The fields of `data` are those of the table of 9.2.
- The schemas are generic: none names a framework, a provider or a model (REQ-AI-003); the provider and the model are plain values of `provider` and `model`.
- The agent is an `actor` with `kind=agent`; the value `agent` must exist in the actor kind enum of T-02.2. The identity of the agent is independent of the process and of the model (REQ-AI-002): `from_agent_id` and `to_agent_id` identify agents, `resource` identifies the process.
- `usage` has only `input_tokens`, `output_tokens` and `total_tokens` (REQ-AI-012, Q05-5): the schema has no cost field.
- Adding an enum value is a MINOR change of the contract (REQ-AI-005, REQ-VER-003).
- Approvals and policies stay in the contract even if unused (Q05-6: "they already exist" in the agent).
- Questions to the maintainer (the specification does not list the values):
  1. The values of `outcome`, `finish_reason`, `decision` and of the AI error categories. They should come from what the existing agent and Langfuse already record (Q05-1), not from a guess.
  2. Where does the optional content go when full prompts or tool results are switched on (T-09.3)? The nine schemas have no content field, and the attributes are limited to 256 characters per value (REQ-CTR-010). Optional fields in `data`?

## Acceptance criteria

- Each schema accepts its valid sample and rejects one with a missing required field, a wrong type and a value outside its enum.
- A usage object with a `cost` field is rejected.
- A provider and a model invented for the test validate without a schema change.
- The generator gives the enums and types for both languages and CI sees no difference.

Ends with the checks of the README section 3 green in every language the task names.
