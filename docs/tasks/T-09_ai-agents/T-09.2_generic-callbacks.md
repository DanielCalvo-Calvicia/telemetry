## Goal

In Go and in Python: `outbound/ai_runtime/`, one callback API for own agents and local inference engines, so an agent reports model calls, tool calls, hand-offs, approvals and denials without knowing any framework (REQ-AI-004, REQ-AI-007, REQ-AI-009).

## Design notes

- One callback per event type of T-09.1 (model invoked, completed, failed; tool called, completed; hand-off; approval requested, resolved; policy denied). The callbacks build the events and send them to the `AITelemetrySinkPort` (T-03.2); they hold no third-party library, so this adapter lives in the core (REQ-AI-009, REQ-DST-004).
- The life cycle of an agent run uses the `execution.*` events of T-07.2, with `parent_execution_id` for subagents and `child_execution_id` for a hand-off (REQ-AI-004).
- Retries, timeouts and cancellations (REQ-AI-007): each retry increments `attempt` and the execution goes through `retrying`; a timeout ends in `timed_out` and a cancellation in `cancelled`, validated by the transitions of T-07.1.
- One process can host several agents and providers (REQ-AI-002): the agent id comes from the call context of T-03.8, not from a global.
- The callbacks are observers. They return nothing that a caller could use to allow or deny an action (REQ-AI-008, checked in T-09.3).
- The Python API is synchronous and the library runs its own worker thread (Q07-7).
- Questions to the maintainer:
  1. Does the library generate `invocation_id` and `call_id` (UUIDv7) when the consumer gives none?
  2. Which names do the callbacks have? They follow `naming.md`; the list is written in `docs/api/api.md` and reviewed there.

## Acceptance criteria

- A run with a model call, a tool call, a hand-off and an approval produces events that validate against the schemas, in both languages.
- A retry produces a higher `attempt` and a `retrying` execution state; a timeout and a cancellation end in their terminal states.
- A subagent execution has the `parent_execution_id` of the agent that started it.
- Two agents in one process produce events with their own `actor.id`.
- A failing sink never raises into the agent code (ADR-005).

Ends with the checks of the README section 3 green in every language the task names.
