## Goal

Implement the `LocalSpoolPort` in Go over a SQLite file: write before send, delete on confirmation, order kept, and a quota (REQ-SPL-001).

## Design notes

- A module of its own at `go/pkg/spool/sqlite/` with its own `go.mod`, a minimum core version pinned, the driver of T-06.2 and its own tag `go/pkg/spool/sqlite/vX.Y.Z` (ADR-013, Q09-3). The project imports it and passes it to the core in code; it never registers itself on import (REQ-ARC-013).
- The directory comes from the consumer; the library never picks a path. One file per destination, so the quota of 256 MiB (default, Q03-5) is per destination. The file name is derived from the destination name; the exact rule is written in the layout of T-06.1.
- Operations the port needs: append a batch, read the next batch in order, delete what the destination confirmed, report used size and quota, and remove records by class for the full-spool policy of 10.3 (that policy is T-06.5). If the port of T-03.2 does not have these operations, T-03.2 is amended in this change.
- A corrupted record is isolated and reported with a classified error; the adapter keeps serving the valid ones (REQ-SPL-002). The adapter returns the count; T-06.5 puts it in diagnostics.
- An unreadable or unwritable directory at start is a classified error; T-06.5 turns it into the degradation to `retry` (REQ-SPL-003).
- The file opens in the mode the layout of T-06.1 says and refuses a file whose `user_version` it does not know.
- Tests live inside the module (`internal/tests/` mirroring the code) because the module is built alone; the usual rule of black-box tests holds. The rule that a nested module can use the core's `internal/` packages is verified here (known risk of PR-001).

## Files

- `go/pkg/spool/sqlite/go.mod`, `spool.go`, `external/` (all `database/sql` calls), `error/`, `helpers/` (record encoding, quota arithmetic)
- `go/pkg/spool/sqlite/internal/tests/` (adapter tests, a temporary directory per test)
- `go/go.work` gets the module (local work and CI)
- Fixtures: `integration-tests/fixtures/storage/spool_three_records.sql` (T-06.1), and a corrupted one `spool_one_corrupted_record.sql`

## Acceptance criteria

- Events appended are read back in the same order and are deleted only after the confirmation call.
- After closing and reopening the file, unconfirmed events are still there.
- At the quota the adapter refuses or removes records as the port says, and the used size is reported.
- A record with damaged content is isolated and counted; the next valid record is returned.
- The module builds with `CGO_ENABLED=0`, and the core module does not list the driver in its `go.mod`.

Ends with the checks of the README section 3 green in every language the task names.

## Verification

Black-box tests of the adapter on a temporary directory (order, restart, confirmation, quota, a corrupted record, an unknown `user_version`); `go build` of the core showing no driver; the checks run inside the module with `go.work` disabled.
