## Goal

The same behavior and the same file layout as the Go adapter, over the standard `sqlite3` module (REQ-SPL-004, REQ-ARC-009).

## Design notes

- Public package `telemetry.spool.sqlite`, in `python/src/telemetry/spool/sqlite/`, with the same folders as the Go module (`external/`, `error/`, `helpers/`) and the same file names (REQ-ARC-014).
- It implements the `LocalSpoolPort` of T-03.2 with the same operations as T-06.3: append, read the next batch in order, delete on confirmation, size and quota, remove by class, isolate a corrupted record.
- It reads the DDL of `contracts/storage/` (T-06.1): the layout is not written a second time in Python code. The version in `PRAGMA user_version` is checked on open.
- `sqlite3` is in the standard library, so the extra has no third-party dependency. The proposal keeps an extra for symmetry (`telemetry[sqlite]`, REQ-DST-002). Question to the maintainer: is the extra still wanted for the spool, since there is nothing to install?
- The worker thread of T-05.1 is the only one that uses the connection, or each thread opens its own; the choice is made with the `sqlite3` rule on threads and written in the Design notes of the code. It must work inside an `asyncio` program (REQ-DLV-002).
- The minimum Python is 3.10 (D-08); the SQLite version bundled with the interpreter of the pilot board (Python 3.11.4) must support WAL and `user_version`, checked at start with a clear error.
- A file written by the Go adapter must open and read here and the other way round; that is proved in T-06.7.
