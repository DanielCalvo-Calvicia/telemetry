## Goal

Prove that the two languages share the files: a spool written by Go is read by Python and the other way round, and a reader opens a destination file read-only while the writer writes (REQ-SPL-004, REQ-CNF-006, Q09-5).

## Design notes

- Three scenarios: Go writes a spool and Python reads and confirms it; Python writes a spool and Go reads it; one language writes the SQLite destination in a loop while a reader (the other language, opened read-only) counts rows and checks `user_version`.
- No helper binaries are committed (CLAUDE.md). Each side is an ordinary test that reads the directory from a variable of the test environment (a test may read it; the library does not, ADR-004) and skips when it is not set. A step of CI, or the maintainer by hand, runs the writer test, then the reader test, then the reverse. The runner of T-12.1 will take these steps over; they do not wait for it.
- The tests need both Go and Python, so they run in CI and on the maintainer's machine; they are not part of the Python package.
- What is asserted: same events, same order, same classes, a damaged record isolated the same way in both, and a writer that is never blocked or failed by the reader.
- Data comes from the shared fixtures of T-06.1, with placeholder events only.

## Acceptance criteria

- The three scenarios pass in both directions on the same directory.
- A spool file with one damaged record is read by the other language with that record isolated and the others delivered.
- A reader never gets a lock error that fails the writer, and the writer's rows are all visible after it ends.
- The tests skip, and say why, when the directory variable is missing.

Ends with the checks of the README section 3 green in every language the task names.

## Verification

Run the writer step and the reader step in order, in both directions; check that the tests report a skip with no variable and that no database file is left in the repository.
