## Goal

Write the two file layouts once, in `contracts/storage/`, so Go and Python write and read the same files (REQ-SPL-004, REQ-OUT-009).

## Design notes

- Destination layout (decided, REQ-OUT-009, Q09-5): one `events` table with the whole envelope as JSON plus indexed columns `occurred_at`, `recorded_at`, `event_type`, `severity`, actor id and `event_id`; indexes on `occurred_at`, `recorded_at`, `event_type` and actor id so a UI can filter and sort. The file is opened in WAL mode; the layout version is in `PRAGMA user_version`; a reader opens the file read-only, never writes, and runs on the same machine because WAL does not work over a network share. Retention is done only by the writer.
- Spool layout: PR-001 fixes only the requirements (a SQLite file, one per destination because the quota is per destination, readable by both languages, an order that is kept, a priority class per record for the policy of 10.3, a way to isolate a corrupted record, REQ-SPL-002). The columns are proposed in this task and confirmed by the maintainer in review.
- Questions to the maintainer: is `event_id` unique in the destination table (a resend would then be ignored)? How is the spool quota measured: payload bytes or the size of the file and its WAL?
- Timestamps in the columns use the fixed format of REQ-CNF-003, so a text sort is a time sort.
- The envelope JSON stored is the canonical one (T-02.5), already masked (ADR-006).
- The layout versions start at 1 and follow the rule of REQ-VER-003: a new optional column is a MINOR change of the layout, anything else a MAJOR one. This is the same rule as for the contract, applied by analogy; the maintainer confirms it.
- Binary files are not committed (CLAUDE.md): the fixtures are SQL text that a test loads into a temporary file.

## Acceptance criteria

- Each layout document states the table, every column with its type and meaning, the indexes, the version and the rules of use.
- The destination layout states WAL, `user_version`, read-only readers, same machine, reader never writes, and retention by the writer only.
- The two `.sql` files load without error in the SQLite shell and in Python's `sqlite3` and give the documented `user_version` and indexes.
- Every link resolves and no real host, path or account appears.

## Verification

Load each `.sql` file into a temporary database with `sqlite3` and check the tables, indexes and `PRAGMA user_version`; a link check over the new documents. The same files are exercised by the tests of T-06.3, T-06.4 and T-06.6.
