## Goal

Choose the SQLite driver of the two Go SQLite modules and record the choice in an ADR, before any Go SQLite code (D-01, Q09-4).

## Question

Q09-4 already settled that the driver is pure Go, with no cgo (the maintainer wanted speed in Q08-4, and then chose C, pure Go, in Q09-4). What is still open:

1. Which pure-Go driver? The checks it must pass: it builds with `CGO_ENABLED=0`; it cross-compiles to the ARM board of the pilot; it supports WAL, `PRAGMA user_version` and a read-only open; its license is fine for a public repository; it is maintained.
2. Does the maintainer want the optional benchmark against the cgo driver before the first release (PR-001, "Known risks": a benchmark can reopen the choice), or is the choice closed?
3. Do the two SQLite modules (spool and destination) use the same driver? The proposal is yes, so a project that imports both downloads one.

## Resolution

Awaiting the maintainer.

## Files

- A new ADR in `docs/decisions/` (the next free number) with the driver, its version, the checks it passed and the benchmark decision
- The row of that ADR in [docs/README.md](../../README.md)

## Acceptance criteria

- The ADR names one driver and the version range, and says how each check was verified.
- It records whether the benchmark will be done, and when.
- It states that the driver is a dependency of the SQLite modules only and never of the core.
- Every link resolves.

## Verification

Read the ADR against the checks above; a build of a tiny test program with `CGO_ENABLED=0` for the host and for an ARM target, recorded in the ADR.
