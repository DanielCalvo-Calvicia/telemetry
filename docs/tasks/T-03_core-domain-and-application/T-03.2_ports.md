## Goal

Define the outbound ports of the application layer and a fake of each, so services can be tested without an adapter.

## Design notes

- Ports of section 7.1 of the specification, in `application/ports/outbound/`: `ClockPort`, `IDGeneratorPort`, `ConfigurationPort`, `LogSinkPort`, `EventSinkPort`, `MetricsSinkPort`, `TraceSinkPort`, `DeviceTelemetrySinkPort`, `AITelemetrySinkPort` and `LocalSpoolPort`. The old library has `ClockPort`, `IDGeneratorPort` and `LogSinkPort` (read, not edited).
- REQ-OUT-001: ports with identical semantics may share a generic abstraction; payloads that differ semantically are not forced into an untyped interface. Open question for the maintainer, decided before the sink ports are written: do the log, device and AI sinks share one `Send(event)` shape, or does each have its own typed method? The plan lists them as separate ports; this task defines them with the minimum surface the epics T-04 to T-11 need and no more.
- `ConfigurationPort` hands the core the configuration the consumer passed in; it reads no file and no environment (REQ-ARC-007, ADR-004).
- `ClockPort` gives the wall time and a monotonic reading (REQ-CTR-007, REQ-CTR-008) and, when known, `clock_source` and `clock_synced`. `IDGeneratorPort` returns UUIDv7 values (the adapters of the clock and of the generator are written in T-03.9, where the dependency question of T-03.1 is answered).
- The sink ports receive an already masked, already validated event and return a result that says accepted, dropped or failed; a sink never throws to the caller (ADR-005, REQ-DLV-005).
- `LocalSpoolPort` is only the contract here (append, read in batches, acknowledge, size, clean up); the SQLite adapter is T-06.
- Fakes live next to the tests, not in the library: `go/internal/tests/fakes/` and `python/internal/tests/fakes/`. They record calls and can be told to fail.

## Files

- `go/internal/application/ports/outbound/` (one file per port, e.g. `clock_port.go`, `id_generator_port.go`, `log_sink_port.go`)
- `python/src/telemetry/internal/application/ports/outbound/` (the same names, `clock_port.py`, ...)
- `go/internal/tests/fakes/` and `python/internal/tests/fakes/` (a fake per port)
- `go/internal/tests/application/ports/` and `python/internal/tests/application/ports/` (tests of the fakes and a compile-time check that a fake satisfies its port)

## Acceptance criteria

- Each port is an interface (Go) or an abstract protocol (Python) with a doc comment that starts with its own name.
- The application layer imports only the domain; no port mentions HTTP, SQLite or a vendor type.
- Every fake satisfies its port and can be told to fail or to return a delay; a test proves each.
- Go and Python have the same ports with the same method names under the naming rule.
- Ends with the checks of the README section 3 green in every language the task names.
