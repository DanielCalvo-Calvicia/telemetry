## Goal

The immutable types of the envelope, validated at construction, with no import from another layer.

## Design notes

- Value objects: severity, event id (UUIDv7), UTC instant, resource, actor, context and attributes. Base value objects (`domain/base_value_objects/`) hold the shared shapes, for example a bounded string and a non-empty identifier, which the value objects wrap (the layout of REQ-ARC-014).
- Severity and actor kind come from the generated enums of T-02.4; this task wraps them, it does not redefine the values (REQ-CNF-001).
- Event id: a UUIDv7 (REQ-CTR-009, Q02-2); it is not derived from a timestamp alone. The value object validates an existing id and does not generate it: generation sits behind `IDGeneratorPort` (T-03.2). The old library uses `github.com/google/uuid`; whether the new Go core keeps it as its only third-party dependency is a question for T-03.2 (the adapter).
- UTC instant: holds a UTC time and refuses another zone; the time format is the one of T-02.5. `resource.time_zone` is a plain IANA name kept for display and never used to compute a time (ADR-012).
- Attributes accept only scalars and lists of scalars (REQ-CTR-010). Their numeric limits (32 keys, 64, 256) are T-03.5; this task defines the type and the scalar rule only.
- Resource needs `service_name` and `instance_id`; the instance id is generated at start if the consumer gives none (section 5.2), using the port, not here.
- Domain code imports the standard library only; names are descriptive snake_case for locals (CLAUDE.md), `PascalCase` for exported Go identifiers, the rule of `naming.md` for Python.

## Acceptance criteria

- Each value object rejects an invalid input with the sentinel of T-03.7 (or a provisional local one replaced there) and exposes no setter.
- A UUIDv7 passes, a v4 and a malformed string fail; a non-UTC instant fails; a nested value in attributes fails.
- Severity has exactly the six values of the contract and maps to the generated enum.
- The domain package of each language imports nothing from `application/`, `infrastructure/` or `composition_root/` (the test of T-01.4).
- Go and Python accept and reject the same inputs (the same table of cases).
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Table-driven black-box tests in both languages over one shared list of valid and invalid inputs; the architecture tests of T-01.4.

## Notes

**Done 2026-10-29** (Go 1.25.5, Python 3.11.1). Two agents wrote the code in parallel from one shared table of cases that the coordinator wrote first; the coordinator verified independently and wrote the documents.

- **Built.** Base value objects `Identifier` and `HexDigits`; value objects `EventID`, `UTCInstant`, `ResourceIdentity`, `ActorIdentity`, `CorrelationContext`, `EventAttributes`; constructors for the generated `Severity` and `ActorKind`. See section 2.9 of the architecture document for the rules.
- **Shared tables.** `integration-tests/fixtures/value_objects/` has 10 files and 88 cases; the same cases pass in Go and in Python. **One case flipped on purpose** (a UUIDv4 marked valid) makes both languages fail; restored, both pass.
- **Verification.** Go: `gofmt` and `goimports` clean, vet and build clean, all tests pass (the architecture test included), coverage **99.3%**; the domain imports only the standard library and itself, and the base package imports nothing of the domain. Python: `ruff` clean, **113 tests**, coverage **100%**. The registry: `REQ-CTR-005` and `REQ-CTR-009` now have tests (13 of 130 covered, 109 pending, 8 without a task); `REQ-CTR-001` moves to T-03.3 and `REQ-CTR-010` stays on T-03.5.
- **Choices.** The new names differ from the generated wire types (`Resource`, `Actor`, `Context`, `Attributes`) to avoid a clash; the mapping is T-03.3. An absent optional field is not the same as an empty one (functional options in Go, `None` in Python). The event id check uses the standard library, no uuid library: the question of `github.com/google/uuid` stays with the adapter of T-03.2.
- **Behavior changes in what existed.** `FormatUTCTime` now rejects year 0 (the format is `0001` to `9999`, as in Python) and its error no longer says the offset in seconds; the code `event_schema_invalid` and `errors.Is(..., ErrNonUTCTime)` still hold. `format_utc_time` raises `NonUtcTimeError` for a value that is not a datetime (it was an `AttributeError`). The placeholder `go/internal/tests/domain/doc.go` was removed because real tests now live there.
- **Known differences between the languages, left for T-03.1's successors.** A composite constructor in Go joins every failed field with `errors.Join` (compare with `errors.Is`); Python raises one exception that lists the failed fields. Go accepts named scalar types and typed slices in attributes (it uses `reflect`); Python accepts lists and tuples. The numeric null-versus-empty rules of the serialization are T-03.3.
- **Python 3.10** was kept by construction (no `StrEnum`, no `datetime.UTC`) but only the local interpreter ran; CI runs 3.10.
