## Goal

Wire the core and expose the one function a project calls to build it, with the adapters it chooses passed in code.

## Design notes

- REQ-ARC-013 and ADR-013: `New(config, adapters...)` builds the core; the project imports the adapters it needs and passes them. The configuration carries only adapter settings, never an adapter name; adapters never register themselves on import. In Python the same shape: `telemetry.new(config, *adapters)` (naming rule of T-02.1).
- No mutable global state (REQ-ARC-006). A convenience global instance is optional and documented; it is not built here (see the epic).
- The composition root (`go/internal/composition_root/{config,containers,dependencies}`) wires the services of T-03.3 to T-03.8 in the order of T-03.3 (build, validate, mask, limit, hand over). Only this layer imports concrete adapters (REQ-ARC-003); one dependencies file per adapter (CLAUDE.md).
- The system clock and the UUIDv7 generator are infrastructure adapters of two ports of T-03.2 and no other task writes them: they are written here, ported from `internal/logging/infrastructure/outbound/systemclock` and `uuidgen`. Question to the maintainer: does the Go core keep `github.com/google/uuid` (its only third-party dependency today, which has a v7 generator) or write UUIDv7 itself (REQ-ARC-005)? Default: keep it.
- `Shutdown` exists as a stub that returns an empty result until T-05.4 gives it the real `flush` and `shutdown` (REQ-DLV-010). A `durable` destination without a spool port is refused at start (see T-03.6).
- Decided (T-01.1, 2026-10-28): the public package that holds `New`, `Shutdown` and the shared types is `go/pkg/telemetry`; every adapter stays in its own `go/pkg/<functionality>/<adapter>` package.
- Layers stay: domain imports nothing from the others; application defines ports; `external/`, `error/` and `helpers/` folders per adapter.

## Acceptance criteria

- With the fakes of T-03.2, `New(config, fake_sink)` returns a core that turns one input into one masked, limited, valid event delivered to the fake sink; the same in Python.
- Two cores in one process do not share state.
- An invalid configuration makes `New` return a classified error naming the field; `Shutdown` returns without error.
- A test greps the sources: no global mutable variable, no `os.Getenv`, no adapter self-registration.
- The architecture tests of T-01.4 pass; an event built in Go and in Python has the same fields.
- Ends with the checks of the README section 3 green in every language the task names.

## Notes

**Done 2026-11-02** (Go 1.25.5, Python 3.11.1). The coordinator wrote the 15 shared cases and the list of public names first (the expected bytes computed independently); two agents wrote the code in parallel (both were stopped by a usage limit and resumed; the Go one was cut off while applying edits and finished on its second resume); the coordinator verified independently and wrote the documents.

- **Built.** The `EventPipelineService` and its routing, `Destinations`, `EmitResult` and `ShutdownResult`; the system clock and the UUIDv7 generator (`infrastructure/outbound/shared/`); the options, the dependencies files and the `Core` of the composition root; the public package `go/pkg/telemetry` and the Python package `telemetry`. See section 2.17 of the architecture document.
- **Verification.** All 15 shared cases give the exact expected bytes, results and problems in Go and Python on the first run, with no edit of any fixture; one expected value changed on purpose (`masked_before_the_sink`) made both languages fail, restored both pass. The **seven hand-computed UUIDv7 layout values were computed a third time independently in Node.js and equal the Go and the Python helper**. A smoke program in each language, with the real clock and the real generator, emitted `log.entry.recorded` with a password in the message and in the attributes: both sinks received the event masked, with a UUIDv7 event id and instance id. Go: `gofmt` and `goimports` clean, vet and build clean, all tests pass (architecture included), coverage **98.2%** (`internal` and `pkg`); `go.mod` has no `require` line; `go doc ./pkg/telemetry` documents the package. Python: `ruff` clean, **404 tests**, coverage **100%**; `pyproject.toml` has no runtime dependency. The registry: `REQ-ARC-005`, `REQ-ARC-006`, `REQ-ARC-013` and `REQ-SEC-001` have tests (31 of 130 covered, 91 pending, 8 without a task).
- **Open question, decided differently from the task default.** The task kept `github.com/google/uuid`; the UUIDv7 is written by hand in both languages instead (reasons in the architecture document). The maintainer was not asked.
- **Choices.** Routing by the first segment of the event type; no destination gives the reason `no_destination`; a sink that panics or raises gives `sink_panicked`; the system clock reports no source and no sync state (so no clock attribute); the options append; a nil option is ignored (in Go a typed nil inside an interface is not detected); the Go generator never lets the UUID time prefix go back; `Option` is a Protocol class in Python so that it has a docstring.
- **Known gaps.** `Shutdown` is a stub (T-05.4); sinks are called synchronously (T-05); the spool port is required for `durable` but not used (T-06); the thin public wrappers for profiles other than `Microservice` and for four options are not exercised by their own tests in Go (they delegate; the composition options are tested); the PEM block is not tested in the `context` place because an identifier cannot hold a line break; a Python sink that returns something that is not a `SendResult` counts as failed. The Python `e2e` shared test uses a few internal helpers (`EventId`, `UtcInstant`, `canonical_json`) that the public package does not export. The global-state test has an explicit allow-list of read-only tables that already existed (Go: six names and four reflect type descriptors; Python: seven). The Go race detector was not run (no cgo). `REQ-ARC-012`, the public packages `<functionality>/<adapter>`, waits for the first adapters.
