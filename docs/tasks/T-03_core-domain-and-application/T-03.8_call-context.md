## Goal

Carry the identity and the correlation of a call through the program, migrated from the old library, so every log attaches them when they exist.

## Design notes

- Today `pkg/logging` carries the application, the instance, the process id and the indentation in `context.Context` (README.md: "Call context ... Implemented"), with the call-depth helper in `internal/logging/application/call_depth` and `NewRequestContext(ctx, "my-app", "instance-1")` as the public entry. Read that code and keep its behavior; the new API names follow `naming.md`.
- New content (REQ-LOG-005, REQ-CTR-005): application (`resource.service_name`), instance (`resource.instance_id`), execution id, trace id, span id and correlation id, plus the indentation of the call depth. Resource identity, actor, execution and correlation stay separate concepts: one process can host several actors.
- Go: values travel in `context.Context` under an unexported key type; no global state (REQ-ARC-006). Python: `contextvars`, which also works with threads and `asyncio` tasks (Q07-7: the API is synchronous but a consumer may run it inside `asyncio`).
- The context never carries secrets, request bodies or arbitrary payloads (REQ-LOG-006). It accepts only identifiers and the depth.
- W3C Trace Context propagation over HTTP belongs to T-10; this task only stores `trace_id` and `span_id` and attaches them. An incoming id is treated as data, not authorization (REQ-TRC-003); validate its shape (hex length) here.
- The indentation rule of the console output is a presentation concern of T-04.2; the value is stored here and the adapter decides how to draw it. Open question: whether the indentation is part of the envelope `context` or only an attribute of the console adapter. Proposed: not part of the envelope; awaiting the maintainer.

## Acceptance criteria

- A context built with application, instance and execution id gives them back; a context with none gives empty values, not errors.
- Two concurrent calls (goroutines, threads) never see each other's values.
- Call depth increases and decreases as in the old library, on the old test cases.
- A malformed trace id or span id is rejected or ignored with a classified result and never raises to the caller.
- Ends with the checks of the README section 3 green in every language the task names.
