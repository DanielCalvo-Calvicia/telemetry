## Goal

Carry the identity and the correlation of a call through the program, migrated from the old library, so every log attaches them when they exist.

## Design notes

- Today `pkg/logging` carries the application, the instance, the process id and the indentation in `context.Context` (README.md: "Call context ... Implemented"), with the call-depth helper in `internal/logging/application/call_depth` and `NewRequestContext(ctx, "my-app", "instance-1")` as the public entry. Read that code and keep its behavior; the new API names follow `naming.md`.
- New content (REQ-LOG-005, REQ-CTR-005): application (`resource.service_name`), instance (`resource.instance_id`), execution id, trace id, span id and correlation id, plus the indentation of the call depth. Resource identity, actor, execution and correlation stay separate concepts: one process can host several actors.
- Go: values travel in `context.Context` under an unexported key type; no global state (REQ-ARC-006). Python: `contextvars`, which also works with threads and `asyncio` tasks (Q07-7: the API is synchronous but a consumer may run it inside `asyncio`).
- The context never carries secrets, request bodies or arbitrary payloads (REQ-LOG-006). It accepts only identifiers and the depth.
- W3C Trace Context propagation over HTTP belongs to T-10; this task only stores `trace_id` and `span_id` and attaches them. An incoming id is treated as data, not authorization (REQ-TRC-003); validate its shape (hex length) here.
- The indentation rule of the console output is a presentation concern of T-04.2; the value is stored here and the adapter decides how to draw it. Open question: whether the indentation is part of the envelope `context` or only an attribute of the console adapter. Proposed: not part of the envelope; awaiting the maintainer.

## Acceptance criteria

- A context built with application, instance and execution id gives them back; a context with none gives empty values, not errors.
- Two concurrent calls (goroutines, threads) never see each other's values.
- Call depth increases and decreases as in the old library, on the old test cases.
- A malformed trace id or span id is rejected or ignored with a classified result and never raises to the caller.
- Ends with the checks of the README section 3 green in every language the task names.

## Notes

**Done 2026-10-30** (Go 1.25.5, Python 3.11.1). The coordinator wrote the shared tables first (22 id cases and 6 mapping cases, the expected bytes computed independently); two agents wrote the code in parallel; the coordinator verified independently and wrote the documents.

- **Built.** `CallContext`, its validated constructor, the storage (`context.Context` in Go, `contextvars` in Python), the deeper indentation, the new request context and the mapping to the correlation context of the event. See section 2.16 of the architecture document. The six old tests of `call_depth` were ported to both languages.
- **Verification.** Both tables pass in Go and Python with no edit of any case; one expected value changed on purpose (`mapping.json`) made both fail, restored both pass. Go: `gofmt` and `goimports` clean, vet and build clean, all tests pass (architecture included), coverage **98.7%**. Python: `ruff` clean, **320 tests**, coverage **100%**. Concurrency: 64 goroutines in Go; 64 threads and 16 asyncio tasks in Python; none sees another's values. The Go race detector was not run (cgo is not available here).
- **A difference found and fixed in review.** Go validated the application and the instance given to the request context and Python did not; Python now does too.
- **Open question, decided with the default.** The indentation is **not** part of the envelope; the console adapter decides how to show it (T-04.2). The maintainer was not asked.
- **Choices.** The old per-request process id is the correlation id, taken from `NewEventID` of the identifier generator port (no new port method). The all-zero rule for trace and span ids (W3C) is applied here, not in the value objects of T-03.1. The application and the instance stay in the call context but are not in the envelope context. A `CallContext` built without the constructor has indentation 0 in Go and 1 in Python (a Python dataclass default): only the constructor guarantees the starting indentation. A failing request-id generator is classified `event_build_failed`, the catalog having no more specific code.
- **Known gaps.** The logger does not attach the ids yet (T-04.1: `REQ-LOG-005`, `REQ-LOG-006` stay pending there). HTTP propagation of the W3C headers is T-10. The race detector has not run on the Go concurrency test. The check that a message holds no value skips values that are blank or very short (a blank always appears in any message).
