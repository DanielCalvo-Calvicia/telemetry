## Goal

The sentinels and exceptions of the core, with the same error codes in both languages, so the root cause is never lost.

## Design notes

- CLAUDE.md: sentinels live in `application/errors.go` and `domain/errors.go` and are composed with `errors.Join`, so a caller can test the root cause with `errors.Is`. The old library has the same shape in its own `errors.go` files (read, not edited).
- Python: an exception hierarchy with one base class for the library and subclasses per layer; a chained cause (`raise ... from ...`) keeps the root cause, the same role as `errors.Join` (Q07-8: PEP 8 and the Go layers).
- Codes come from `contracts/errors/` (T-02.3) through the generated code of T-02.4. REQ-CNF-004: the validation and configuration codes are identical; the message text may differ. Each error carries its code, the field or event type involved and no value (the value may be a secret).
- The hot path never throws (ADR-005, REQ-DLV-002): these errors are returned as values by the services and raised only by construction and start (invalid configuration, REQ-CFG-002). Say so in the doc comment of each.
- Error translation of an adapter stays in the adapter's `error/` folder (CLAUDE.md); this task defines only the sentinels of the domain and application layers.
- Open question to the maintainer: whether the generated code owns the sentinels (one per catalog code) or the hand-written layer files wrap them. Default: the generated file defines the codes; `errors.go` and `errors.py` define the sentinels and map them by code.
- Go exported identifiers have doc comments that start with their own name (`go doc` rule of CLAUDE.md).

## Acceptance criteria

- Every code of the catalog that a core layer can produce has a sentinel (Go) and an exception class (Python), with the same code string.
- `errors.Is` finds the root cause through a join of two sentinels; in Python the cause is reachable through the chain.
- No error message contains a value passed by the caller, proven by a test with a sentinel-looking secret.
- A test lists the codes of both languages from the shared fixture and compares them.
- Ends with the checks of the README section 3 green in every language the task names.

## Verification

Black-box tests in both languages; the shared codes table compared by a small test in each language.

## Notes

**Done 2026-10-30** (Go 1.25.5, Python 3.11.1). The coordinator extended the contract first (the category `internal`, four codes, the generated code) and wrote the shared table of 29 failures; two agents wrote the code in parallel; the coordinator verified independently and wrote the documents.

- **Built.** `value_objects.CodeOf` (Go) and `error_code_of` (Python): the code of any error of the core; the application services return classified errors with the new codes (`event_build_failed`, `masking_failed`, `limits_failed`, `instance_id_unavailable`); a single root `TelemetryError` for the Python hierarchy, enforced by a test. See section 2.15 of the architecture document.
- **Open question, decided with the default.** The generated file owns the codes and the hand-written layers map their sentinels to them (a table in Go, class attributes in Python). The maintainer was not asked.
- **A decision the task had left open (T-03.3): the code of an application failure.** There was no code in the catalog for a port failing, so the contract got a category `internal` and four codes (a MINOR change). The maintainer was not asked; if a different set of codes is preferred, the catalog, the generated code and the table change.
- **Mutation proof.** One expected code changed on purpose (`masking_failed` expected as `limits_failed`) made both languages fail; restored, both pass.
- **Verification.** Go: `gofmt` and `goimports` clean, vet and build clean, all tests pass (architecture included), coverage **98.7%**; the generator re-run changes nothing. Python: `ruff` clean, **295 tests**, coverage **100%**. The registry: `REQ-CNF-004` has tests (27 of 130 covered, 95 pending, 8 without a task).
- **The leak test found four leaks in code that had passed review.** Python put the caller's text in the message of an invalid severity and of an invalid actor kind; Go put the extra pattern (through the compile error of the regular expression engine) and the class name and rule into the messages of an invalid masking option. All four are fixed and the test now keeps them out. The two Go ones are a behavior change of T-03.4 (the message no longer quotes the pattern).
- **Known gaps.** The cause of an error built by a consumer's adapter is kept as it is (it may hold a value); the two producers whose cause comes from a port (`event_build_failed`, `instance_id_unavailable`) are tested with a cause that holds no secret. The sentinels of the future adapters and capabilities add their own codes (T-04 onwards). The Go `CodeOf` table does not know the application sentinels (the domain cannot import the application); they always travel inside a classified error.
