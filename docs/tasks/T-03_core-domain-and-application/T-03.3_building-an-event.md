## Goal

One application service that turns what a capability gives it into a complete, valid envelope.

## Design notes

- REQ-CTR-008 and ADR-012: the service sets `occurred_at` (given by the consumer, otherwise the time of the call) and `recorded_at` (only from `ClockPort`; a consumer value is ignored and never accepted). When the data carries `observed_at`, `occurred_at` equals it. Both are UTC in the fixed format of T-02.5. Q09-1: the two times are the generation time and the recording time; there is no local time and no offset.
- It adds `clock_source` and `clock_synced` to `attributes` when the clock port knows them (Q07-13: stored in every call, not only for devices). If the port does not know, the keys are absent, not `false`.
- `event_id` comes from `IDGeneratorPort` (UUIDv7). `schema_version` is the constant of the generated contract. `resource` is the one of the configuration (T-03.6); `context` comes from the call context (T-03.8).
- The order inside the core is fixed and documented: build the envelope, validate `data` against its schema (T-02.6), mask (T-03.4), apply limits (T-03.5), hand over to the sinks. No path skips masking (ADR-006). This task builds the envelope and calls the validator; the later steps are plugged in by their tasks and T-03.9 wires the chain.
- Hot-path rule (REQ-DLV-002, ADR-005): the service never throws to the caller; it returns a result value. A rejected event is counted.
- An event type unknown to the registry is rejected with the error code of T-02.3 (open point: a consumer extension type; not allowed in v1, say so in the architecture document).
- Open question to the maintainer: whether the monotonic duration measurement of REQ-CTR-008 stays in the clock port or becomes a small separate value object. Default: in the port, with a method that returns elapsed time.

## Acceptance criteria

- With a fixed clock and a fixed id generator, the same input gives the same envelope in Go and in Python.
- A caller-supplied `recorded_at` is ignored; a supplied `occurred_at` is kept; with no `occurred_at` it equals the time of the call; with `observed_at` in `data` the two are equal.
- `clock_source` and `clock_synced` appear only when the clock port reports them.
- An invalid `data` or an unknown event type returns a classified result and never raises or panics.
- Ends with the checks of the README section 3 green in every language the task names.

## Notes

**Done 2026-10-29** (Go 1.25.5, Python 3.11.1). Two agents wrote the code in parallel; the coordinator wrote the nine shared cases first (the expected bytes computed with Node.js, not by the code under test), verified independently and wrote the documents.

- **Built.** `EventBuilderService` with its input DTO, mappers and errors in both languages; `UTCInstant.parse` (Go `ParseUTCInstant`) for the `observed_at` rule; the constant `SchemaVersion` / `SCHEMA_VERSION` = `0.1`; `FailWith` on the id-generator and configuration fakes. The order of the steps and the rules are in section 2.11 of the architecture document.
- **Verification.** All nine shared cases give the exact expected bytes in Go and in Python on the first run. **One expected value changed on purpose** (`clock_synced` true to false in `building/clock_known.json`) makes both languages fail; restored, both pass. Go: `gofmt` and `goimports` clean, vet and build clean, all tests pass (the architecture tests included), coverage **99.4%**; the application imports only the domain and itself. Python: `ruff` clean, **162 tests**, coverage **100%**. The registry: `REQ-CTR-001` and `REQ-CTR-008` now have tests (17 of 130 covered, 105 pending, 8 without a task).
- **Open question, decided with the default.** The monotonic duration of REQ-CTR-008 stays in the clock port (`MonotonicNanoseconds`, T-03.2); no new value object. The maintainer was not asked.
- **Choices.** One clock read per event (so `occurred_at` and `recorded_at` are equal when nothing else is given). A failing port gives a plain "event could not be built" error with no catalog code (T-03.7). A panic is recovered and its value is dropped on purpose, because it could hold data. Python also turns a `data` that is not a mapping into `event_schema_invalid`; Go cannot have one (its type is a map).
- **Known gaps.** `schema_version` is a hand-written constant, not generated as the design said (the generator emits no version; a drift test or a generated constant is a small follow-up for T-02 or T-03.9). The envelope is not validated as a whole against `envelope.schema.json` (only `data` is). `observed_at` can only be tested with an injected permissive validator until a device event type is registered (T-08). The builder returns an unmasked envelope: nothing must send it before T-03.4 and T-03.9. The count of rejected events (REQ-DGN-001) is wired in T-05.5.
- **Left to the next tasks.** Masking (T-03.4), limits (T-03.5), configuration profiles (T-03.6), the error model and codes (T-03.7), the call context (T-03.8), the composition root and the public entry point (T-03.9).
