# config

The schema of the configuration (T-03.6, REQ-CFG-001): the option names, the types, the defaults and the profiles (`microservice`, `cronjob`, `worker`, `robotics`, `offline_device`). One logical model for both languages. The library reads no file and no environment (ADR-004): the consumer loads its configuration and passes it in, so this folder describes the shape and never a value of a real project. [config.schema.json](config.schema.json) is that model (T-03.6): the sections `resource`, `delivery`, `limits`, `spool` and `masking`, each property with its type and its `x-env` name. [http_destination.schema.json](http_destination.schema.json) holds what the HTTP destination adds to the shared client (T-04.5). [file.schema.json](file.schema.json) holds the settings of the file destination (T-04.3). [console.schema.json](console.schema.json) holds the settings of the console destination (T-04.2). [http_client.schema.json](http_client.schema.json) holds the settings of the shared HTTP client (T-04.4), which every HTTP adapter embeds. [aws_http.schema.json](aws_http.schema.json) holds the settings of the AWS HTTP adapter (T-04.6). The defaults and the profiles are code, not part of the schema. The model is hand-written in Go (`go/internal/infrastructure/config`) and in Python (`python/src/telemetry/internal/infrastructure/config`) and a test in each language keeps it equal to the schema, to `docs/configuration/environment-variables.md` and to `.env.example`.
